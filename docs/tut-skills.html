Skills

A skill is a small capability that Claude can use during a conversation. The bundled skills load when they match your request. To add your own skill, put a Markdown file in the skills/ folder.

You do not name a skill. Ask for the result, and Claude selects the skill whose description matches. This page shows these items:

  • The bundled skills and the selection of a skill.
  • How to write and use your own skill.
  • How Claude writes skills when you correct its work.

What a skill is

A skill is a Markdown file with a small YAML header (the frontmatter) and a body. The frontmatter gives the name of the skill and the conditions for its use. The body contains the instructions that the model obeys when the skill runs. At startup, Whisper Studio reads each file in skills/ and makes a tool from it.

Progressive tool disclosure is on by default. Thus, the model does not get the full schema of each skill tool at the start. The model gets a short index of names and descriptions.

The model loads the full definition of a skill with tool_search. It can also use the skill_list and skill_invoke tools, which are always available. A skill is a tool. Thus, Claude reads the descriptions and calls the skill that matches.

There are two types of skills:

  • Prompt skills. The body is guidance that the model reads and uses, for example a style for meeting notes. No code runs on this Mac.
  • Executor skills. The frontmatter names an executor. When the skill runs, backend code runs. The server code must register the executor.

Built-in tools and bundled skills

The core capabilities are built-in tools. Examples are web search, web fetch, Python in the sandbox, shell commands, AWS operations, document analysis, and transcript summaries. They are in the code, they are always available, and they do not show in the skills panel. You do not enable them. Ask for the result, and the model selects the tool. Refer to Agent tools → Built-in core tools.

The skills below are the bundled set. They load when they match the request. You can edit, rename, disable, or delete them in "Settings", "Skills", as your own skills.

SkillFunctionExample request
Meeting NotesFull meeting notes: overview, decisions, a table of owner, action, and deadline, discussion points, blockers, and next steps."Write up minutes for this meeting."
TranslateTranslates the transcript or a text to a target language."Translate this into Kurdish."
Presentation BuilderWrites a slide deck from a topic or from source material."Build me a 10-slide deck on this."
Catch UpA recap for a person who joined late, and questions to ask next."Catch me up on what I missed."

Meeting Notes and Catch Up use the live or recorded transcript. The server gives the transcript to the skill, as for the built-in Summarize Transcript tool. The app makes a long transcript shorter before these skills run. Refer to Transcript summarization.

The web search tool uses a Tavily API key. Add the key in "Settings", "General", in the field "Tavily API Key (for web search)". The app saves the key in config.user.json. The TAVILY_API_KEY environment variable has priority over the saved key.

With no Tavily key, the tool does not return search results. If an Amazon Bedrock AgentCore browser MCP server is enabled, the tool tells the model to use that browser. If not, the tool returns instructions for the configuration. The other tools work in all cases. Refer to Environment variables.

See a skill run

When Claude calls a skill, a small indicator shows in the message. The skill and skill_input SSE events carry it. Click the indicator to open the trace: the skill name, its input, and its result. Each tool call has the same trace. Thus, a skill does not run without a record.

Enable and disable skills

"Settings", "Skills" lists each skill. You can enable or disable each skill and read its definition. When you disable a skill, the app removes it from the catalog, and Claude cannot select it.

The app keeps the on and off state in skills_config.json in the data folder. The skill files stay the same. Thus, when you disable a bundled skill, the app does not edit or delete it. The toolbar of the panel has these buttons:

  • "+ New Skill": write a skill in the app.
  • "Import skill": add skills that a different person shared.

Each skill has a unique name. Case and the difference between "-" and "_" do not make a different name. Thus, "Deploy-Staging" and "deploy_staging" are the same name. The app does not save or rename a skill when a different skill has that name.

The editor does not replace the skill that you have. It shows "A skill named deploy_staging already exists". To continue, use a different name, or delete the skill that you have.

The import dialog has an "Overwrite existing" checkbox. It is clear at the start. When the checkbox is clear, the import does not replace the skill that you have. The dialog shows "Not imported, a skill with the same name exists" and the names. When you select the checkbox, the import replaces the skill that has the same name.

The app keeps the old skill until the copy is complete. If the copy fails, the app puts back the old skill. The import can also replace a skill that came with the app. It does not use the name of a built-in tool.

"Settings", "Import project" copies skills, instructions, and MCP servers from a Claude Code or Codex CLI project. Refer to Import a Claude Code or Codex project.

Write a custom skill

A custom skill is one Markdown file in skills/. The frontmatter is the most important part:

  • name is the name for a call of the skill.
  • description is the text that Claude reads to select a skill. Write it as you explain the skill to a colleague. The selection uses only this text.
  • triggers is optional. It lists example phrases for the skill.

This example is a minimal prompt skill. Save it as skills/standup-notes.md:

---
name: standup_notes
description: Turn rough standup jottings into a tidy per-person update with blockers called out. Use when the user pastes standup notes.
triggers: standup, daily update, blockers, what I did, yesterday, today
input_schema:
  notes:
    type: string
    required: true
    description: The raw standup notes to format
---

Rewrite the notes as a clean standup update. For each person, list:
Yesterday, Today, and Blockers. Put anything that sounds like a blocker
under Blockers even if it was not labelled that way. Keep it terse.

To add and use the skill:

  1. Make the file

    Put your .md file in skills/. Or click "+ New Skill" in the skills panel and write the skill in the app. The app validates and loads a skill from the panel immediately. You do not restart the app.

  2. Make sure that the skill loaded

    Open the skills panel, or ask Claude to run skill_list. The list shows your skill with its description and the number of triggers.

  3. Ask for the result

    Write a request that matches the description, for example "clean up these standup notes". Claude selects the skill. You do not type its name.

  4. Optional: call the skill by name

    Ask Claude to use the skill by its name. Claude then calls skill_invoke with the name of the skill and your input.

The selection uses the description. If Claude does not select a skill, write the description again. Say clearly when to use the skill, and add some realistic triggers. If two skills have the same function, disable one of them.

skill_list, skill_invoke, and skill_manage

Three tools let Claude use skills directly, without the automatic selection:

skill_list
Returns each available skill with its name, description, and triggers. Claude calls it to find the skills before it selects one.
skill_invoke
Runs a skill. It receives a skill_name and an input text, and applies the skill to the input.
skill_manage
Writes skills. It can read a skill and its file list, and make a skill. It can change text, add or remove a support file, and delete a skill that it made. Refer to Skills that Claude writes.

Usually, you do not think of the first two tools. Claude uses them when a request is not clear, or when you name a skill.

Folder skills

A skill can also be a folder. The folder contains a SKILL.md file and its scripts, references, and assets. The app loads the full folder. The instructions of the skill can tell Claude to run the scripts of the folder.

You cannot edit a folder skill in the app. Edit its files on disk. You can mark a folder skill as trusted. Then, when the skill runs a script from its own folder, the app approves that command automatically. An untrusted folder skill shows the usual approval card. Refer to Permissions & approvals.

Skills that Claude writes

Skills are also the procedures of Claude: how to do a type of task in the way that you like. Thus, Claude writes and changes skills. After a turn, a review in the background examines the turn. It asks: did the user correct the work procedure, or did a procedure occur that a new session can use again? If yes, the review writes it with skill_manage.

The same review writes the memories. Refer to Memory & WHISPER.md. A memory is a fact for all sessions. A skill shows how to do one type of task.

The review runs only in the Hybrid and Cloud model modes. It does not run in Local mode, which is the mode of a new install.

The review changes a skill before it makes a new skill. It uses this sequence:

  1. Change a skill that ran in this turn

    If a skill ran and you corrected its output, the review corrects that skill. It reads the current text first, and then replaces an exact passage.

  2. Change a skill for that type of task

    If a skill for the task is available, the review changes it, also when it did not run in this turn.

  3. Add a reference file

    Long text goes into a file in the references/ folder of the skill.

  4. Make a new skill

    The review makes a new skill only when no skill matches. The name describes a type of work, for example deploy_staging or weekly_report.

You control the result:

  • A skill that Claude made has created_by: agent in its frontmatter.
  • Claude can delete only a skill that it made. Claude can edit your skills, but only you can delete them, in "Settings".
  • The app validates each name. A name cannot be the same as a built-in tool name. Each file path must be in the folder of the skill. Support files can go only in references/, scripts/, templates/, or assets/.
  • The instructions file can be maximum 64 KB. A support file can be maximum 200 KB.
  • Each change is a file on disk. Open the skills panel to read, edit, or disable the skill.

A toast tells you of each change, for example "Skills updated: 1 skill updated". To stop these changes, disable the skill_self_improvement feature flag in "Settings". Then skill_manage refuses each change, and the review writes only memory.

Sandbox and guardrails

The tools that a skill uses have the same protections as all tools. Two built-in tools show this:

run_python runs in the sandbox

The built-in run_python tool runs code in a subprocess, with a short timeout, in the macOS sandbox. It is for quick calculations.

aws_boto3 is read-only

The built-in aws_boto3 tool accepts only read operations (list, describe, get). For write actions, Claude uses the aws_cli tool, which shows an approval card.

The main protection is the macOS sandbox (sandbox-exec). The read-only Boto3 guard and the command validator are more layers on top of the sandbox. Refer to Sandbox & security and the security model.

WARNING: Read an imported skill before you mark it trusted. The instructions of a skill run with the tools of Claude. Examine its SKILL.md and its scripts as you examine code from a different person.

Where the skills are

The skills are in your user folder:

  • Mac app: ~/.whisper/skills/. At the first start, the app copies the bundled skills into this folder one time. After that, the app does not copy them again. Thus, a skill that you rename or delete stays renamed or deleted.
  • Source install: the skills/ folder of the checkout.
skills/
The skill definitions: one Markdown file for each skill, and a subfolder for each folder skill.
skills_config.json
The disabled and trusted skills, in the data folder, separate from the skill files.
server/skills.py
Reads the files and the frontmatter, and makes the tool catalog. The HTTP handlers are in server/skills_routes.py.
server/agent_tools/skill_manage.py
The skill_manage executor: name validation, path limits, size limits, and the delete rule.
