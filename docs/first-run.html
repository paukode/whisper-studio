First run & verify

You opened the Mac app for the first time, or bash setup.sh printed a URL. This page is the short checklist that confirms the things you actually came for work: chat, on-device transcription, spoken conversations, and the workspace tools.

Whisper Studio is one process serving one origin, so there is nothing to "connect" between a frontend and a backend. What is left is telling the app which AWS region to use, picking a model, then exercising each subsystem once. Work through the steps in order; each one leaves you in a good state for the next.

New machine, nothing installed yet? Do the Installation walk-through first, then come back here. This page assumes the app is already open, whether that is the Mac app or the URL setup.sh printed.

First, the Local-mode notice

The very first launch shows a one-time dialog headed You're starting in Local mode. It is not an error. A fresh install is seeded with model_mode: local, so nothing leaves your machine until you choose otherwise, and the dialog explains the three modes (Local, Hybrid, Cloud) and where to change them. Dismiss it, or use its button to jump straight to Settings → Model mode. It never appears again.

Local mode does not stop you using cloud models. The app ships no on-device chat model, so the model picker would otherwise be empty; instead it falls back to showing every model. You can chat on Bedrock from the first minute, switch the mode to Hybrid or Cloud whenever you like, and install an on-device model from Settings → Models → Discover when you want to run chat locally too. See Model modes.

The healthy-install checklist

Six steps. The first two are one-time configuration; the rest prove each subsystem is alive. If steps 3 and 4 pass, your install is healthy.

  1. Open the app

    From a source install, look at the end of the terminal output for a line with an address, typically http://127.0.0.1:8000; the script also opens it for you unless you passed --no-open. If port 8000 was busy, the script takes the next free one, so read the URL it actually printed rather than assuming 8000. In --dev the address you want is the Vite one (from 5173), not the backend. You should see the Whisper Studio interface, not a blank page. (A blank page usually means the frontend bundle is missing; re-run bash setup.sh, or bash setup.sh --new for a clean rebuild. Note that --new backs up your config and reseeds it with the first-run defaults, so you would then re-add your Tavily key and any custom settings, or restore them from the backup.)

  2. Set your region, then pick a model

    Click the gear icon, then go to Access and usage → Keys and permissions → API keys:

    • Bedrock Region must match the region where your model is enabled. This is almost always the same region you used in aws configure. A mismatch here is the single most common first-run error (see below). It is pre-filled with us-east-1.
    • Tavily API Key only if you did not export TAVILY_API_KEY in your shell. If the env var is set, the app uses it and this field can stay empty (the env var wins if both are present). Skip this entirely if you do not need web search yet.

    Click Save, close Settings, and pick a model from the model chip in the composer toolbar. There is no default-model field in Settings. Sonnet 5 is a good balance of speed, cost, and capability while you confirm things work; you can switch any time from the chip or with /model.

  3. Confirm chat: type "hello"

    In the chat input, type hello and send it. If the reply streams back token by token, chat works and your AWS access is good. If you get an error instead, jump to Common first-run stumbles below; the message text tells you which problem you have.

  4. Confirm transcription: click Record

    Click Record in the top-right. The browser (or macOS, in the Mac app) asks for microphone permission the first time; grant it once. Speak a sentence or two. A live transcript should appear with speaker labels attached. The first recording is slightly slower to start because the on-device speech model (Parakeet by default, or Whisper or Canary) downloads and loads into memory on first use; after that it is warm. Transcription runs entirely on your machine, so it needs no AWS setup and works even offline.

  5. Optional: confirm voice with the Talk button

    The waveform button between the microphone and Send starts a spoken conversation. If it is greyed out, hover it: the tooltip names the reason, usually that Amazon Nova 2 Sonic is not enabled in your Bedrock region, that no AWS credentials were found, or (source installs only) that the backend's Python is older than 3.12. Click it and say something; the assistant answers out loud and everything it says is written into the chat. See Voice conversations.

  6. Optional: connect a workspace folder

    Creating and saving new files needs no workspace at all: ask for a file and the assistant resolves the destination from your words ("in Downloads" goes to ~/Downloads), defaults to ~/Documents/<filename> otherwise, builds the file, and shows an approval card; approving moves the finished file into place, and the assistant never asks where to save. The created file then renders as a clickable link that opens with your OS default app.

    What a workspace unlocks is the IDE and repo tools: connect a folder with the Workspace control and Claude can read your files, edit existing code, run commands, and use Git, all gated by your permission mode. You can skip this if you only want chat and transcription; connect a folder whenever you are ready to code.

If steps 3 and 4 both succeed, you have a working install. Chat and transcription are the two independent subsystems, so passing both means AWS, the local model runtime, and the microphone permission are all in order.

Run /doctor for an automated check

Rather than eyeballing each subsystem, you can let the app check itself. Type /doctor in the chat input and send it. This runs an automated AWS-credentials and Bedrock-connectivity check and reports the results inline in the chat.

A healthy result confirms five things, without you having to record or connect anything:

  • AWS credentials resolve (from env vars or ~/.aws/credentials).
  • Bedrock connectivity: a Claude model is invocable in your configured region, so a chat turn can actually reach a model. (The ping uses a known-good model, not necessarily your configured default.)
  • Workspace: the connected folder, if any, still exists on disk.
  • Sessions DB: the session store opens and answers a query.
  • Config: the effective config loads, reporting your model, effort, and region.

If /doctor flags something, its output points at the specific failing check, which is faster than reading a raw exception from a failed chat turn. Run it any time later, too, if chat suddenly stops working after an AWS or config change.

Backend changes do not hot-reload. If you edit a server/*.py file, restart the process before re-running /doctor, or you will be checking the old code. The frontend, in --dev mode, does reload on its own.

Common first-run stumbles

Almost every failed first chat is one of two AWS problems, and the error message tells you which one. Read the text of the error before changing anything.

AccessDeniedException (or "Could not invoke model"). Your AWS user does not have Bedrock permission, or the Claude model is not enabled in the region you selected. Grant the user Bedrock access in IAM, and enable the specific Claude model in the Bedrock console for that region.

"You don't have access to the model with the specified model ID." This is almost always a region mismatch. The model is enabled somewhere, just not in the region Settings points at. Make the Bedrock Region in Settings match the region where you enabled the model (and where aws configure is pointed). This is the same failure the Installation guide's troubleshooting table calls out.

A few non-AWS stumbles round out the set:

SymptomWhat it means and the fix
Blank page in the browser The frontend bundle is missing. Re-run bash setup.sh, or bash setup.sh --new for a clean rebuild. Note that --new backs up your config and reseeds it with the first-run defaults, so re-add your keys and settings afterwards.
The URL at 8000 does not load Port 8000 was in use, so the script chose another port. Read the URL the script actually printed rather than typing 8000 by hand.
Microphone permission never prompts The browser may have remembered a denial. Re-grant microphone access for the site in the browser's site settings, then click Record again.
Recording misses system audio In the Mac app, open the headphones menu beside Record and arm System audio or a single app; the first capture triggers the macOS System Audio Recording prompt (macOS 14.4 or later). In a browser the microphone cannot hear what the Mac is playing: share a Chrome tab, or route audio through a virtual device. See Voice & meetings.
The Talk button is greyed out Hover it for the actual reason. Usually Amazon Nova 2 Sonic is not enabled in your Bedrock region, no AWS credentials were found, or the backend's Python is older than 3.12. See Requirements.
The model picker shows no on-device models Expected: a fresh install ships none. Install one from Settings → Models → Discover, which grades each model against your machine's memory first.

For anything not listed here, the Installation guide has a fuller troubleshooting table covering prerequisites, network errors, and ports.
