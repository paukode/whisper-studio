Environment variables

A short list of shell variables that override stored config and control how the server binds and starts. The environment is the highest-priority config layer, so anything set here wins over the project and user layers.

The environment variables below are the ones you are likely to set: variables that steer binding and startup (HOST, PORT, BACKEND_PORT, NO_OPEN), one that opens up LAN access (WHISPER_TRUSTED_ORIGINS), and one that supplies a secret (TAVILY_API_KEY). Everything else is configured through the Settings UI or the user config file. A few lower-level knobs also read the environment (TZ for cron scheduling; WHISPER_RG_PATH, WHISPER_SEARCH_TIMEOUT, WHISPER_GLOB_LIMIT, and WHISPER_GREP_LIMIT for the search tools; WHISPER_HOME to relocate the app home for a packaged install; WHISPER_USER_DIR to relocate the user-data root that defaults to ~/.whisper; and WHISPER_DATA_DIR to override where app data lives, also settable as the data_dir config key), but the defaults suit almost everyone. See Configuration for how the layers stack.

The variables

NameDefaultEffect
HOST 127.0.0.1 Bind address. Set HOST=0.0.0.0 to bind every interface, but on its own that is not enough to reach the app from another device: the Host-header guard still returns a 403 until you also set WHISPER_TRUSTED_ORIGINS. Trusted networks only, and read the warning below first.
PORT 8000 Backend port, honored only when you start the server directly (python -m server.main). Via setup.sh the launcher picks its own port starting at 8000 and increments while busy, overwriting anything you exported, so always read the URL the script actually prints.

TAVILY_API_KEY unset Web-search key. Overrides the tavily_api_key config value. When both are set, the env var wins, so key rotation is one export away.
WHISPER_TRUSTED_ORIGINS unset Comma-separated list of extra hosts or origins the Origin/Host guard should trust, e.g. WHISPER_TRUSTED_ORIGINS=192.168.1.50,my-box. Required when you bind HOST=0.0.0.0 and browse from another device: the guard rejects any request whose Host is not localhost with a 403, so set this to the host or origin you actually type into the browser. See Exposing on the LAN.
NO_OPEN unset Set NO_OPEN=1 to skip auto-opening the browser at startup. Same effect as the --no-open flag. Useful for SSH and headless sessions.

Binding and startup

The three binding variables shape how the process comes up. The most common way to set them is a one-line prefix in front of the launcher:

HOST=0.0.0.0 PORT=8080 bash setup.sh --no-open

The two startup paths treat PORT differently. Launching through setup.sh, the script always starts scanning at 8000 and climbs to 8001, 8002, and so on while the port is busy - it overwrites any PORT you exported, so setting it before bash setup.sh has no effect. setup.sh then propagates the resolved value into BACKEND_PORT so the Vite dev proxy points at wherever the backend actually landed. Running the server directly with python -m server.main instead, your exported PORT is honored as-is. Either way, read the URL the process actually prints rather than assuming the value you set.

BACKEND_PORT only matters in dev mode (bash setup.sh --dev), where the browser talks to the Vite dev server and Vite proxies API calls to the backend. In production mode (the default), FastAPI serves the SPA and the API on the same origin, so there is nothing to proxy and you can ignore BACKEND_PORT entirely.

Exposing on the LAN

By default the server binds 127.0.0.1, so it is reachable only from the machine it runs on. Setting HOST=0.0.0.0 binds every interface, but that alone does not make the app usable from another device. The Host-header guard rejects any request whose Host is not localhost, 127.0.0.1, ::1, or 0.0.0.0 with a 403 - and a LAN browser sends Host: 192.168.x.x, so every request, the initial page load included, is refused. To actually reach it from another device you must also set WHISPER_TRUSTED_ORIGINS to the host or origin you browse from:

HOST=0.0.0.0 WHISPER_TRUSTED_ORIGINS=192.168.1.50 bash setup.sh --no-open

The API is unauthenticated. Whisper Studio assumes it runs on localhost for a single trusted user. There is no login. When you bind HOST=0.0.0.0, anyone who can reach the port can drive the agent, run sandboxed commands, read your workspace, and spend your Bedrock budget. Do this only on a network you fully control, and prefer an SSH tunnel over raw LAN exposure.

The Origin/Host guard gives partial, not complete, protection here. It rejects cross-site browser requests, so a malicious web page you happen to visit cannot quietly script your local instance through the browser. It does not stop a deliberate non-browser client (curl, a script, another program on the LAN) from calling the API directly, because those clients simply send the expected Origin and Host headers. Treat the guard as a defence against drive-by browser attacks, not as authentication. See the security model for the full boundary picture.

Secrets

TAVILY_API_KEY enables the web_search tool (web_fetch needs no key at all). Reading it from the environment is the recommended path because it keeps the key out of the on-disk user config file and makes rotation trivial:

echo 'export TAVILY_API_KEY=tvly-...' >> ~/.zshrc
source ~/.zshrc

If you also paste a key into Settings, the environment value takes precedence. Without a key set by either path, web search is simply unavailable; chat, transcription, and the workspace tools all work as normal. See Web research for how the tool uses it.

Where the environment fits

Config resolves in five layers, highest priority first. The environment sits at the top, so a value exported in your shell overrides all four config layers below it:

Environment
Shell variables (HOST, PORT, BACKEND_PORT, WHISPER_TRUSTED_ORIGINS, TAVILY_API_KEY, NO_OPEN). Highest priority. Set per-launch or in your shell profile.
<workspace>/.whisper/settings.json
Project layer. Per-project model, region, and permission mode. Edited through the Settings UI.
config.user.json (or legacy config.json)
User layer, at the app home: the repo root in a dev checkout, or WHISPER_HOME in a packaged install. Your own deltas on top of the shipped defaults. Edited through the Settings UI or by hand. A dev checkout still seeds this file from the example config on first run; a legacy monolithic config.json keeps acting as the user layer until it is split on migration.
config.example.json
SYSTEM layer, at the repo root. The app-owned shipped defaults and model catalog, read live on every config load (not just copied once), so new template models need no separate sync step.
Code defaults
Built-in fallbacks in server/infrastructure/config.py, used only when the SYSTEM file cannot be read.

Only the binding and secret keys have an environment override. Most settings (model, region, effort level, permission mode, feature flags, cost caps) live only in the project, user, and system layers. For the complete field-by-field list, see Settings & config keys.

The environment layer is shell-only. There is no field in the Settings UI for HOST, PORT, BACKEND_PORT, WHISPER_TRUSTED_ORIGINS, or NO_OPEN. To change them, set the variable and restart the server.
