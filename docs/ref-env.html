Environment variables

A short list of shell variables that control how the server binds and starts and where it keeps its files. Only two of them override a stored config key: TAVILY_API_KEY and WHISPER_DATA_DIR.

The variables below are grouped by what you would reach for them to do: binding and startup, credentials, and file locations. Everything else is configured through the Settings panel or the user config file. A variable reaches the server only when you start it from a shell that exports it (a source install). The Mac app starts its server with its own environment and does not read your shell profile. A long tail of tuning knobs also reads the environment; those are collected in one Advanced and internal table at the end, and their defaults suit almost everyone. See Configuration for how the layers stack.

Binding and startup

NameDefaultEffect
HOST 127.0.0.1 Bind address, read by a source install only: the Mac app always binds 127.0.0.1 on its own port (41410). Set HOST=0.0.0.0 to bind every interface, but on its own that is not enough to reach the app from another device: the Host-header guard still returns a 403 until you also set WHISPER_TRUSTED_ORIGINS. Trusted networks only, and read the warning below first.
PORT 41430 Backend port, honored only when you start the server directly (python -m server.main). setup.sh always picks the port itself: 41430, or the nearest free port within 5 of it, and it stops with an error when all of them are in use. It overwrites anything you exported, so always read the URL the script prints. The Mac app uses its own port, 41410.
BACKEND_PORT 41430 Read by vite.config.ts so the dev proxy targets the real backend port. It matters only in dev mode (bash setup.sh --dev), where the browser talks to the Vite dev server (port 41460, or the nearest free one) and Vite proxies API calls to the backend. setup.sh sets it from PORT, so you rarely set it by hand.
NO_OPEN 0 Read by setup.sh. Set NO_OPEN=1 to skip auto-opening the browser at startup. Same effect as the --no-open flag. Useful for SSH and headless sessions.
WHISPER_TRUSTED_ORIGINS unset Comma-separated list of extra hosts or origins the Origin/Host guard should trust, e.g. WHISPER_TRUSTED_ORIGINS=192.168.1.50,my-box. Required when you bind HOST=0.0.0.0 and browse from another device: the guard rejects any request whose Host is not localhost with a 403, so set this to the host or origin you actually type into the browser. It takes effect when the server starts. See Exposing on the LAN.
TZ unset The host timezone that wall-clock cron schedules use: checked first, then the /etc/localtime symlink. If neither names a zone, or the name is not a known zone, the schedule fails with an error. A non-blank cron_timezone wins over it, and a per-job schedule.tz wins over both. See Scheduled tasks.

Credentials

Whisper Studio never stores AWS credentials of its own. It authenticates to Amazon Bedrock the way any AWS SDK does: the variables below, then the shared files in ~/.aws (including SSO). A shell export reaches only a server started from that shell. The Mac app does not see your shell exports, so there Bedrock uses the default profile in ~/.aws/config and ~/.aws/credentials.

NameDefaultEffect
AWS_ACCESS_KEY_ID / AWS_SECRET_ACCESS_KEY unset Static credentials for Bedrock. The /doctor check reports whether either these or a profile is present. Stripped from the environment handed to MCP child processes.
AWS_BEARER_TOKEN_BEDROCK unset A Bedrock API key. It authenticates chat and the other Bedrock calls, and /doctor reports it. Voice mode does not accept it: Nova Sonic needs signed AWS credentials. It is not stripped from MCP child environments.
AWS_PROFILE / AWS_DEFAULT_PROFILE unset Named profile from ~/.aws to authenticate with, including an SSO profile. The usual choice on a work machine.
TAVILY_API_KEY unset Web-search key for a server started from your shell. Overrides the tavily_api_key config value; when both are set, the env var wins. A change needs a server restart. In the Mac app, set the key in Settings > Keys and permissions > API keys. Stripped from MCP child environments.

File locations

Three roots decide where your data lands, and a fourth variable points at the docs. A source install keeps everything in its checkout: setup.sh stops with an error when WHISPER_HOME or WHISPER_USER_DIR is set, so it never mixes its data with the Mac app's. The Mac app sets WHISPER_HOME, which splits the roots apart. Relocating a root is mostly useful for tests.

NameDefaultEffect
WHISPER_HOME the repo root The app home. It holds storage/ (the databases: sessions.db and the workspace indexes) and logs/. The Mac app sets it to ~/Library/Application Support/WhisperStudio, and when it is set the user root moves to ~/.whisper.
WHISPER_USER_DIR ~/.whisper when WHISPER_HOME is set, else the repo root The user root: everything you browse, edit or delete by hand. models/, skills/, plugins/, agents/, the config layer, and data/.
WHISPER_DATA_DIR <user root>/data Where app data lives: the result cache, the JSON stores, permissions.json, voiceprints.json, memory and workflows. Wins over the data_dir config key, which is the other way to set the same thing.
WHISPER_DOCS_DIR the docs/ folder beside the server Where the bundled documentation site is read from: the pages served at /docs-site, opened from the ? dock panel, and searched by @docs. Point it elsewhere to serve a different copy.

How binding works

Set a binding variable as a one-line prefix in front of the launcher:

HOST=0.0.0.0 bash setup.sh --no-open
HOST=0.0.0.0 PORT=8080 python -m server.main

setup.sh picks the port itself, so a PORT prefix has an effect only with python -m server.main. Either way, read the URL the process prints rather than assuming the value you set.

Exposing on the LAN

This applies to a source install only; the Mac app always binds 127.0.0.1. By default the server binds 127.0.0.1, so it is reachable only from the machine it runs on. Setting HOST=0.0.0.0 binds every interface, but that alone does not make the app usable from another device. The Host-header guard rejects any request whose Host is not localhost, 127.0.0.1, ::1, or 0.0.0.0 with a 403, and a LAN browser sends Host: 192.168.x.x, so every request, the initial page load included, is refused. To actually reach it from another device you must also set WHISPER_TRUSTED_ORIGINS to the host or origin you browse from:

HOST=0.0.0.0 WHISPER_TRUSTED_ORIGINS=192.168.1.50 bash setup.sh --no-open

The API is unauthenticated. Whisper Studio assumes it runs on localhost for a single trusted user. There is no login. When you bind HOST=0.0.0.0, anyone who can reach the port can drive the agent, run sandboxed commands, read your workspace, and spend your Bedrock budget. Do this only on a network you fully control, and prefer an SSH tunnel over raw LAN exposure.

The Origin/Host guard gives partial, not complete, protection here. It rejects cross-site browser requests, so a malicious web page you happen to visit cannot quietly script your local instance through the browser. It does not stop a deliberate non-browser client (curl, a script, another program on the LAN) from calling the API directly, because those clients simply send the expected Origin and Host headers. Treat the guard as a defence against drive-by browser attacks, not as authentication. See the security model for the full boundary picture.

Secrets

TAVILY_API_KEY enables the web_search tool (web_fetch needs no key at all). Set the key in Settings > Keys and permissions > API keys, which works for every install. For a source install you can instead export it in the shell that starts the server, which keeps the key off disk; that value wins over the one in Settings. With no key, web_search tells the assistant to use an enabled Amazon Bedrock AgentCore browser MCP server if you have one, and otherwise explains how to set up search. Chat, transcription, and the workspace tools work as normal. See Web research for how the tool uses it.

Advanced and internal

These exist for tuning, for tests, and for the Mac app shell to tell the backend where its bundled binaries are. You are unlikely to set any of them by hand, and the app works with all of them unset.

PYTHONPYCACHEPREFIX unset Where .pyc files are written. The Mac app points it at a cache directory because the signed bundle is read-only.
WHISPER_PARENT_PID unset The Mac app shell sets this to its own process id so the backend exits when the app quits rather than outliving it. A non-numeric value is ignored with a warning.

The Mac app sets all four to its own bundled copies, and setup.sh sets ffmpeg, ffprobe and Node to the copies it installs, so neither needs them installed on the machine. Where the environment fits

Config resolves in five layers, highest priority first. The environment layer holds one key only, so most of what you set lives in the layers below it:

Environment
TAVILY_API_KEY over tavily_api_key. Highest priority. The other variables on this page are read by the server, Vite or setup.sh at startup and are not config keys.
<workspace>/.whisper/settings.json
Project layer, edited by hand. It may set bedrock_region, chat_models, chat_models_disabled, default_chat_model, effort_level, permission_explainer_enabled, max_session_cost_usd, max_daily_cost_usd, model_fallback_enabled and feature_flags, plus project hooks. The permission mode is not a project key; it is set for the user only.
config.user.json
User layer, in the user root: the checkout for a source install, ~/.whisper for the Mac app. Your own deltas on top of the shipped defaults. Edited through the Settings UI or by hand; startup never writes it. A fresh install is seeded once with the first-run defaults (local model mode).
config.example.json
SYSTEM layer, at the repo root. The app-owned shipped defaults and model catalog, read live on every config load (not just copied once), so new template models need no separate sync step.
Code defaults
The DEFAULTS in server/infrastructure/config.py, the base layer under config.example.json. They supply every key the example file does not set.

Only two config keys have an environment override: the Tavily key (TAVILY_API_KEY over tavily_api_key) and the data root (WHISPER_DATA_DIR over data_dir, resolved where the data root is read). TZ runs the other way: cron_timezone wins over it. Everything else (model, region, effort level, permission mode, feature flags, cost caps, voice, speakers) lives only in the project, user, and system layers. For the complete key-by-key list, see Settings & config keys.

The environment layer is shell-only. There is no field in the Settings panel for HOST, PORT, BACKEND_PORT, WHISPER_TRUSTED_ORIGINS, or NO_OPEN. To change them, set the variable and restart the server.
