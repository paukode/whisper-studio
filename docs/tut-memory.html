Memory & WHISPER.md

Give Claude a memory that stays after the current conversation, and a file for the permanent facts of your project. Then you do not tell Claude the same facts again.

Memory is on by default. The app records the facts to keep, writes a summary of the conversation, and reads both on the next turns. A project WHISPER.md gives the project context on each turn.

This page shows three different mechanisms:

  • Workspace memory: permanent facts for all the sessions.
  • Session memory: a summary of the current conversation.
  • WHISPER.md and rules: files that you write, or that the assistant writes when you ask.

On by default, in two tiers

Memory is on by default. Two feature flags control it, and both are on by default:

  • auto_memory: the permanent memory, the review that writes it, and the recall.
  • session_memory: the summary of each session.

You do not call a tool or type a command. To disable memory, click the "More" button (···) in the chat box, and then click the "Memory" row. You can also type /memory off.

Local mode only reads memories. A new install starts in Local mode. In Local mode, the app reads the saved memories, but it does not record new memories. The "Memory" row then shows "Recall only". The review after a turn and the consolidation do not run. To record memories, open "Settings", then "Model mode", and select Hybrid or Cloud.

Permanent memory has two tiers. Thus, a fact has a location with or without a workspace:

  • Global memory applies in all workspaces and in a chat with no workspace. It contains facts of you: preferences, role, and feedback on how Claude must work.
  • Project memory applies only in the open workspace. It contains facts of that workspace, for example goals, deadlines, and repository references.

The folder name of a project memory is the name of the workspace folder and a short hash of its full path. Thus, two projects with the same folder name have separate memories. Global memory is in a separate folder, and all chats share it.

Workspace memory: permanent facts

Workspace memory is a small set of Markdown files for each project. The files stay for all the sessions of the project. They are in memory/<workspace-slug>/ in the data folder (refer to Where the files are).

Each file starts with YAML frontmatter: a name, a description of one line, and a type. A short Markdown body follows. An index file, MEMORY.md, lists each file on one line.

The review after a turn saves only some facts. Each fact has one of four types:

TypeContents
userFacts of you: preferences, role, and skills.
feedbackCorrections and instructions on how Claude must work.
projectProject context, goals, and deadlines that are not in the code.
referenceLinks to external systems and resources.

The review does not save facts that the codebase already contains. Examples are the architecture, code patterns, the git history, and a correction that is in a commit. The review also does not save these items:

  • Problems of the environment that you can correct, for example a missing program.
  • Statements that a tool "does not work".
  • Errors that a second try corrected.
  • The story of a single task.

The review after a turn

A review in the background writes the memories. It runs after every third turn, and it does not stop your answer. The review does not send a summary of the chat. It sends the turn again, with the same system prompt, tools, and messages, and one more question: which facts must the app keep? The prompt cache already contains the turn. Thus, the review costs little, and it reads the full conversation.

The review can change only the memory files and your skills. It can also read workspace files. It cannot continue your task. It writes two types of items:

  • Memories, when you gave a permanent fact of you, your preferences, or the project.
  • Skills, when you corrected a work procedure, or when a procedure that you can use again occurred. A memory is a fact for all tasks. A skill shows how to do one type of task. Refer to Skills.

If the model wrote a memory during the turn, the review does not run for that turn.

How the app reads memory

The app does not add all the memory files to each prompt. For each new question, the app reads the list of memory files:

  • If there are 5 files or fewer, the app adds all of them.
  • If there are more than 5 files, a cloud model compares the list with your question and selects maximum 5 files. The default model is Claude Haiku. To use a different cloud model, set auxiliary_models.memory_recall. Refer to Settings & config keys.
  • For an on-device model, and in Local mode, the app does not send the list to a cloud model. It adds the 5 newest files.

Consolidation

The app also joins and cleans the memory files. Each memory tier has its own counter. The consolidation runs for a tier when 24 hours and 5 turns are complete after the last consolidation of that tier. The dream_consolidation feature flag controls it, and it is on by default. It does not run in Local mode.

Read and edit the memory files

  1. Open the viewer

    Click the "More" button (···) in the chat box. Then click "Memory files".

  2. Select a file

    The viewer shows the global memory files and the project memory files.

  3. Change the file

    You can edit or delete the file. You can also move a project memory to the global memory.

Session memory: a summary of the conversation

Session memory is different from workspace memory. It is a summary of the current conversation. Thus, the model does not read all the earlier turns of a long conversation. Session memory is one Markdown file with four sections:

SectionContents
## GoalsThe goals of this session.
## DecisionsThe decisions of the session.
## ContextImportant background facts.
## BlockersProblems that are not solved.

An agent in the background writes the summary. The app adds the summary to the next turns in a <session-memory> block. The summary is short. Thus, a conversation of many hours can continue with no cost to read all the turns again.

When the summary changes

The summary changes after a turn, in the background. It changes only when the conversation grew by a set quantity:

  • A cloud session waits for 200,000 more characters (approximately 50,000 tokens) and 10 tool calls.
  • An on-device session waits for 6,000 more characters. It uses its own model for the summary.

The summary does not stop your answer. If the summary fails, the app does not change the summary for that turn. Refer to the Memory system page.

The app keeps session memory and workspace memory in different files. Workspace memory keeps facts for all the sessions of a project. Session memory is a summary of one conversation. When memory is on, both run.

WHISPER.md and rules: your instructions

The memory above is automatic. The files in this section are your files. The app adds them in full on each turn. The files are in your user folder, not in a workspace. Thus, nothing goes into a repository. The user folder is ~/.whisper for the Mac app, and the checkout folder for a source install.

The assistant writes rules and WHISPER.md files with no approval card in all permission modes except plan mode. In plan mode, a write to these files shows an approval card. This applies only to rules and WHISPER.md files. Other files in the user folder, for example configuration files, plugins, and agent types, obey the permission mode. If you know the Claude Code CLI: WHISPER.md is the same as CLAUDE.md, and rules/ is the same as .claude/rules/.

~/.whisper/WHISPER.md
Your profile: who you are, your tools, and the style of answer that you like. The assistant changes it only when you ask.
~/.whisper/rules/global/rules.md
Rules for all projects, one instruction on each line. The app gives default rules (no emoji, no em dashes). The app also reads each other .md file in this folder.
~/.whisper/rules/<project>/WHISPER.md
The overview of the project: its function, its layout, and how to build and test it. There is one folder for each workspace. The folder name is <folder name>-<8 character hash>, the same name as the memory folder of the project.
~/.whisper/rules/<project>/rules.md
Rules for that workspace only.

In a source install, replace ~/.whisper with the checkout folder.

Put a fact of you or the project in a WHISPER.md. Put an instruction for the assistant in a rules file. Thus, WHISPER.md stays easy to read, and you can see the rules that the assistant added.

"Remember this"

You can add a rule without the files. Say "remember this", "my rule is", "from now on", or "do not do that again". The assistant writes your words as one line in the rules.md of the connected project. If the folder is missing, the assistant makes it.

If you add "always", "everywhere", "all the time", or "in every project", the line goes to the global rules.md. With no workspace connected, a rule also goes to the global file. A fact that you ask the assistant to note goes to the related WHISPER.md. The assistant tells you the name of the file in one line. The rule applies from the next turn. Facts that the assistant finds itself go to memory, not to your rules.

Good contents for a project WHISPER.md:

  • The commands to run, build, and test the project.
  • The words of the domain and the structure of the codebase.
  • Folders that the assistant must not change, generated files, and the branch procedure.

You can edit these files in two ways:

  1. The editor in the app

    Connect a workspace. Click the "More" button (···) in the chat box. Then click "Project memory". The row shows only when a workspace is connected. The editor opens the WHISPER.md of the connected project.

  2. A text editor

    The files are Markdown files in the user folder. Open them in a text editor and save them. The next turn reads the new text. You do not restart the app.

If your repository has an AGENTS.md file

You do not change it. The app reads an AGENTS.md at the workspace root on each turn, together with the project WHISPER.md. The prompt labels it as instructions for other coding tools. If the two files do not agree, WHISPER.md has priority, and the prompt says so. If there is no project WHISPER.md, the AGENTS.md is the only project instruction file. The app does not read a WHISPER.md in the repository.

Keep these files short. The app reads them on each turn, so each turn pays for their input tokens. The app reads maximum 12,000 characters of each file. Put permanent facts and rules here. Let the automatic memory keep the facts that change.

Where the files are

The data folder is ~/.whisper/data for the Mac app, and data/ in the checkout for a source install.

data/memory/<workspace-slug>/
Project memory: the memory files and the MEMORY.md index.
data/global_memory/
Global memory: facts for all workspaces and for a chat with no workspace.
data/session_memory/<session-id>.md
The summary of one conversation.
rules/<project>/
The WHISPER.md and rules.md of the project, in the user folder. The global files are WHISPER.md and rules/global/ in the user folder.
server/memory/
The code of the memory system: the review, the recall, the session summaries, the consolidation, and the tools.
