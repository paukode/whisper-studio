Web research

Ask for current information and get an answer with sources. Claude decides when to reach for the web, runs a search, reads the best pages, and streams back a normal answer with footnoted links. You do not call a tool by hand.

Claude's own knowledge stops at its training cutoff, so anything that happened recently (a launch, a price, a score, a policy change) is a job for the web. When you ask a question like that, Claude can call two tools: web_search to find current results and web_fetch to read the readable text of specific pages. This tutorial shows how to trigger that, what you see while it runs, and how to check the sources.

A Tavily API key gives the best web search. Without one, web_search falls back to an Amazon Bedrock AgentCore browser MCP server if you've enabled one; otherwise it's unavailable, and everything else in the app still works. Setting the key takes two minutes. See Installation (step 3) and Configuration.

Before you start

Web search runs through Tavily, a search API whose free tier covers personal use. You supply the key one of two ways:

  • Environment variable (recommended). Export TAVILY_API_KEY in your shell. The env var overrides any stored value, so rotation is one export away. 
    echo 'export TAVILY_API_KEY=tvly-...' >> ~/.zshrc
source ~/.zshrc
  • Settings UI. Click the gear icon and paste the key into the Tavily API Key field. If both the env var and the Settings value are set, the env var wins.

The tavily_api_key setting ships empty, so web search is off until you add a key. web_fetch (reading a specific URL) does not need Tavily, so pasting a link and asking about it works even before you configure a key.

Ask a question that needs the web

There is nothing to enable in chat. Just ask, and phrase it so it is clear you want current facts (and, if you care, ask for sources).

  1. Open a chat and type your question

    Anything time-sensitive works. For example:

    What did Anthropic announce at their last developer
conference? Cite sources.

  2. Claude decides whether to search

    If the answer is stable and well within its knowledge, Claude answers directly. If it needs fresh facts, it calls web_search on its own. You do not pick the tool.

  3. Watch the Activity row

    Each tool call shows up in the turn's Activity row, the collapsed strip that counts the steps Claude took. Web search and web fetch are read-only, so no approval card interrupts you.

  4. Read the answer with its links

    The answer streams in like any other, with links to the pages Claude relied on. Follow a link to check the source yourself. Asking for sources in the question is what makes those links appear reliably.

Nudge Claude toward the web when it matters: phrases like "as of today", "the latest", or "cite sources" make the current-info intent explicit. If you want a specific page read, paste the URL and say "summarize this".

The two web tools

Research uses two distinct tools with different jobs. Both are read-only.

ToolWhat it doesNeeds Tavily?
web_searchSearches the web through Tavily and returns up to five results, each with a title, a URL, and a short content snippet.Yes
web_fetchFetches one public page over HTTP or HTTPS and returns its readable text: a header with the URL, the HTTP status and the page title, then the HTML converted to plain text with heading and list markers. Long pages are cut at 30,000 characters and the request gives up after 15 seconds.No

web_fetch only reaches public addresses. Private, loopback, and link-local addresses are refused, including the cloud metadata address, so a page cannot talk the app into fetching something on your own network.

A typical research turn chains them: web_search finds candidate pages, then Claude calls web_fetch on the most promising ones to read them in full before it answers. When you paste a URL directly, Claude usually skips straight to web_fetch. For the full tool catalogue, see Agent tools.

Reading a page you paste

You do not have to ask an open-ended question. Paste a link and ask about it directly, and Claude reads that exact page with web_fetch:

Summarize https://example.com/some-long-article and pull
out the three main claims.

Because web_fetch does not touch Tavily, this path works even if you have not set a Tavily key yet. Fetched pages are also sanitized before rendering: a prompt-injected page cannot run scripts in the app. See the security model for how web_fetch output is treated as untrusted.

Limiting where commands can connect

The two web tools above are separate from the network a shell command gets when Claude runs one. That has its own setting in Settings > Permissions, and it has three tiers:

TierWhat a sandboxed command can reach
permissiveAnything. This is the default.
curatedA seed list of common package registries, documentation sites, and developer APIs, plus anything you added.
restrictiveNothing except the domains you added yourself.

The domains you add are custom_allowed_domains, one per line in that panel. An entry covers its subdomains too, so adding githubusercontent.com also allows objects.githubusercontent.com and you do not have to enumerate them. Changing the tier takes effect on the very next command, with no restart. Enforcement reads the hostname out of the TLS handshake and never decrypts anything, which also means it is a strong default rather than an airtight boundary: see Sandbox & security for its limits.

What else fires alongside

Research often pulls in other capabilities without you asking for them by name. Each one shows up as its own step in the turn's Activity row:

analyze_document

When you upload a paper or report instead of (or alongside) searching, it reads the attachment's extracted text back into the turn. See Working with documents.

The translate-text skill

When a relevant source is not in English, Claude can translate the passage it quotes so the answer stays readable. See Skills.

web_search and web_fetch

The two tools above. Search needs the Tavily key; fetch reads URLs you paste.

Check what was searched

You are never asked to trust a claim blindly. Consecutive tool calls in a turn collapse into one Activity row rather than a card per call, and it expands into a one-line summary per step, each of which opens to show that step's raw output. That is your audit trail for a claim.

  • Expand the Activity row to see the exact web_search query and the results Claude got.
  • Open a web_fetch step to see which page was read and the text that came back.
  • Follow the links in the answer to read each source directly.

A step that errored opens the row by default, so a failed search is never hidden behind a chevron.

Under the hood, these are ordinary tool calls in the streaming chat loop. The chat pipeline streams a tool event as each search or fetch starts, which is exactly what the inline indicator renders.

Why research never asks for approval

Web search, web fetch, and document parsing are all read-only. They cannot change your files, run commands, or alter git state, so no approval card appears no matter which permission mode you are in. The worst case for a research turn is a wrong answer, not a harmful action, which is why this journey stays friction-free. Approvals only enter the picture once Claude can write, run, or commit, as in the workspace.

Troubleshooting

SymptomLikely cause and fix
Claude answers from memory when you wanted fresh factsAsk more explicitly ("as of today", "cite sources"), or paste a specific URL so it uses web_fetch.
No search happens at all, everTavily key is missing. Set TAVILY_API_KEY or fill the Settings field, then reload. See Configuration.
Search worked yesterday, fails nowRotated or expired key. The env var is the last layer of the config merge, so it overrides the stored value: re-export it and restart your shell.
A pasted URL will not loadThe page may block automated fetches or be behind a login. Try a public mirror or paste the relevant text directly.
