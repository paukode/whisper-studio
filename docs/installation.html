Installation

Two ways to install on macOS: drag the Mac app out of a DMG, or clone the repository and run one script. This guide assumes no prior tooling, so it installs Homebrew, Python, and the AWS CLI from scratch. Budget 15 to 25 minutes the first time.

Install the Mac app (recommended)

The fastest path on Apple Silicon is the packaged app: no Homebrew, no Python, no cloning a repo. It is the same codebase as the from-source setup below, built into a native shell around the same backend and the same compiled frontend.

  1. Download the latest DMG from the GitHub Releases page.
  2. Open the DMG and drag Whisper Studio into Applications.
  3. Open it from Applications, not from the disk image.

Requirements: an Apple Silicon Mac (M1 or newer), macOS 14 or later. You still set your Bedrock region and pick a model on first run, as described in First run & verify; the app skips Steps 1 to 4 below entirely.

The build is not notarized, so the first launch needs one extra step. macOS shows a warning such as "cannot be opened because the developer cannot be verified" or "the app is damaged". You clear it once, either way:

  • Without Terminal: double-click the app, click Cancel on the warning, open System Settings → Privacy & Security, scroll down to the line about Whisper Studio, and click Open Anyway. Confirm with your password or Touch ID, then open the app again.
  • One Terminal command (the most reliable): 
    xattr -dr com.apple.quarantine "/Applications/Whisper Studio.app"

The same text ships as read me first inside the DMG.

Mac app or source: what is the same, what differs

Both installs run the same FastAPI backend, the same compiled frontend, the same tool catalog, and the same config defaults, so a feature described anywhere in these docs behaves the same in both unless a page says otherwise. Two things genuinely differ: where files live, and two capabilities that only a native Mac shell can provide.

Install from source

Whisper Studio is one local process that serves both the API and the React SPA on a single origin. Getting there is a short chain: install a few command-line tools, connect AWS, clone the repo, run setup.sh, and configure two fields in the app. Click a box below to see what each step does.

Already tooled up? If python3 --version, brew --version, and aws --version all succeed, skip ahead to Step 4 - Get the code and run. If any of them fails, start at Step 1.

Step 1 - Install prerequisites

Four command-line tools have to be present before setup.sh can do its work. Homebrew installs the other three.

ToolWhyCheck
GitClone the projectgit --version
Python 3.12 or newerBackend runtime. The one version gate the script enforces before it touches anything.python3 --version
HomebrewInstalls everything elsebrew --version
AWS CLIBedrock auth for Claude, GPT and voice modeaws --version

First install Homebrew (skip this if brew --version already works):

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

Do not skip the two eval lines. When the installer finishes it prints two eval commands that add Homebrew to your PATH. Run both, then close and reopen Terminal. Without this, the very next command reports brew: command not found.

Then install Git, Python, and the AWS CLI in one line:

brew install git python@3.12 awscli

Node.js is handled for you. You do not install Node yourself. setup.sh installs Node 22.16.0 (pinned in .nvmrc) inside the project venv/ using nodeenv, so it never touches a system Node or your other projects.

Python 3.12 is a hard floor. The Bedrock bidirectional streaming SDK behind voice mode installs only on 3.12 or newer, so an older interpreter would silently give you an app without Talk. If python3 is older or missing, setup.sh says so, offers to run brew install python@3.12 for you (in an interactive terminal), adds it to your PATH in ~/.zshrc, and uses it for the rest of that run. Without Homebrew or an interactive terminal it exits instead of continuing.

Step 2 - Connect AWS

Cloud chat (Claude or GPT) runs on Amazon Bedrock, so the AWS CLI needs credentials. Run:

aws configure

It prompts for an access key ID, a secret access key, a default region, and an output format. For the full walk-through of creating keys and profiles, see the AWS CLI configuration docs.

Regions must match. Whichever region you type here is where Claude must be enabled in your account. Set the same value as the Bedrock Region in Settings later. A mismatch is the most common first-run error (see Troubleshooting). You also need Bedrock model access granted for the Claude models you intend to use. If you want spoken conversations, grant access to Amazon Nova 2 Sonic in that region as well: see Requirements.

Step 3 - (Optional) Tavily key for web search

A Tavily key powers the web_search tool. It is optional: without one, web_search falls back to an Amazon Bedrock AgentCore browser MCP server if you have enabled one, and web_fetch (fetching a URL you give it) works with no key at all. Everything else (chat, transcription, the workspace tools) works regardless. You can add this now or any time later.

  1. Sign up

    Create a key at app.tavily.com. The free tier covers personal use.

  2. Export it in your shell (recommended)

    echo 'export TAVILY_API_KEY=tvly-...' >> ~/.zshrc
source ~/.zshrc

    The env var overrides any value stored in config.user.json, so rotating the key is one export away and the secret stays out of the config file.

  3. Or paste it into Settings

    You can instead paste the key into the Settings UI. If both are set, the environment variable wins.

See Environment variables for the full list of what the shell layer can override.

Step 4 - Get the code and run

There are two ways to get the project onto your machine. Both finish with one command that builds and serves the app, so pick whichever suits you.

Option A - Clone with Git (for developers)

Clone the repository, enter it, and run the setup script:

git clone https://github.com/paukode/whisper-studio.git
cd whisper-studio
bash setup.sh

Option B - Download the ZIP (no Git needed)

If you would rather not touch the command line to get the code, download the project as a ZIP and run the same script.

  1. Download

    On the GitHub repository page, use Code → Download ZIP and save it (for example to your Downloads folder).

  2. Extract

    Double-click the downloaded .zip in Finder. It expands into a whisper-studio folder.

  3. Run setup.sh

    Open that folder, right-click setup.sh, and choose Open With → Terminal. The script runs and prints the URL when the app is ready. That is it - you are good to go.

If double-clicking opens a text editor instead of running it, macOS has not associated .sh files with Terminal. Use the right-click → Open With → Terminal path above, or open Terminal, type bash (with a trailing space), drag the setup.sh file onto the window, and press Enter. On the first run, macOS Gatekeeper may ask you to confirm running a downloaded script.

From here on both options are identical - the rest of this guide applies either way.

What setup.sh does, step by step

On a first run the script works through the whole provisioning pass in this order. Every noisy install step logs to setup.log and prints a single progress line; if a step fails, the tail of that log is printed on the terminal so you do not have to go find it.

  1. Checks Python

    Requires Python 3.12 or newer. If the active python3 is older or missing, the script offers to install python@3.12 via Homebrew, persists it on your PATH, and uses it for the rest of the run.

  2. Pre-flight for a production run

    Before touching the filesystem it checks Homebrew, ffmpeg, ripgrep, curl, and lsof, and auto-installs ffmpeg and ripgrep through Homebrew when they are missing. Anything it cannot fix is collected into one list so you can resolve everything in a single pass. Git and the AWS CLI are deliberately not gated here: the script installs them itself further down.

  3. Creates the venv and installs Python deps

    Builds an isolated venv/ and installs from requirements.txt. It prefers an extension-capable (Homebrew) Python so vector search can use sqlite-vec, referenced by absolute path only, and falls back to a numpy vector search otherwise. Your default python3 and shell config are left untouched.

  4. Fetches Playwright Chromium

    The Playwright pip package carries no browser, so the script runs playwright install chromium for the live-preview browser tools. It is idempotent and skipped once the build is cached.

  5. Installs the remaining system tools

    Through Homebrew, and only when missing: ffmpeg (audio decoding), ripgrep (workspace search), git (skill and plugin cloning, the workspace Git tools), and the awscli. Installing the AWS CLI does not configure it; you still run aws configure once.

  6. Installs Node 22.16.0 inside the venv

    Uses nodeenv to put the version pinned in .nvmrc into the venv, then runs npm install.

  7. Builds the frontend

    In production mode (the default) it runs npm run build, so the backend can serve the compiled bundle. --dev skips the build and starts Vite instead.

  8. Seeds your config on a fresh install

    When neither config.user.json nor a legacy config.json exists, it calls the same migrate_user_config() the packaged app runs on boot. That writes a config.user.json holding the first-run defaults: local mode, with the on-device index backends recorded for later. An existing config is never touched. If you passed a mode flag, the chosen model_mode is written on top.

  9. Installs the on-device serving runtime

    llama.cpp (the llama-server binary) via Homebrew, in every mode, matching the Mac app which bundles it, so a model you install later from Discover serves without re-running setup. The build number matters: anything older than build 10090 cannot load current model architectures, so an outdated install is upgraded. A failure here is reported loudly, because on-device chat has no fallback runtime.

  10. Fetches the always-on speech models

    About 190 MB: the language-ID model (VoxLingua107) and the two speaker encoders (ReDimNet2, the default, and ECAPA, the fallback). Every transcription path needs them and the Mac app ships the same three inside its bundle, so a source install matches. The step is idempotent, and a hiccup fetching ReDimNet2 is reported without failing the install (it then downloads on first use).

  11. Starts the backend and opens the app

    It takes the first free port from 8000 upward, starts python -m server.main, waits up to 90 seconds for /health, prints the URL, and opens it in your default browser. In --dev it also starts Vite on the first free port from 5173 and points you at that instead. Press Ctrl+C to stop.

No chat, transcription, or index weights are downloaded by setup. Apart from the three always-on speech models above, every model arrives on demand with an in-app progress banner, exactly like the Mac app's first launch: the transcription engines on your first recording, the on-device index weights (Qwen3 embed and rerank, GLiNER, about 5 GB) on your first index build in hybrid or local mode, and chat models when you install them from Settings → Models → Discover (a fresh install ships none).

Subsequent runs are fast. When venv/ and node_modules/ already exist, the install steps are skipped. A plain bash setup.sh just rebuilds the frontend and serves it.

setup.sh flags

Flags fall into three groups: what to reinstall, how to serve, and which model mode to provision. With no flags you get production serving in the existing (or cloud) mode.

FlagEffect
--new (or --fresh)Wipe venv/, node_modules/, and static/dist/, then reinstall from scratch. It also takes a timestamped backup of config.json and config.user.json and removes them, so the seeding step recreates a config with the first-run defaults; pricing.json is backed up and rewritten from pricing.example.json. Re-add your Tavily key and any custom settings afterwards, or restore them from the backups (they are the only copy, since both files are gitignored).
--devDevelopment mode: run the backend plus the Vite dev server with hot-module reload, on the first free port from 5173. Open the Vite URL, not the backend; the script opens it for you. Mutually exclusive with --prod.
--prodProduction mode (the default): build the frontend and serve it from FastAPI. No Vite, no HMR.
--cloudStart in cloud mode: all indexing and RAG on Amazon Bedrock. Nothing on-device beyond transcription.
--hybridStart in hybrid mode: pick a backend per capability. The on-device index weights download on your first index build.
--localStart in local mode: everything on-device. Index weights download on first index build; chat models are installed separately from Settings → Models → Discover.
--no-openDo not auto-open the browser (also honored via the NO_OPEN=1 env var). Useful for SSH or headless sessions.
-h, --helpShow all options and exit.

A mode flag writes model_mode into your user config, so it sticks until you change it. Without one, an existing config is honored and a fresh install starts in local mode, the same first-run default as the Mac app. The --dev / --prod and mode flags combine, for example bash setup.sh --dev --cloud. Any other argument is rejected with a pointer to --help.

Two environment variables are worth knowing here. NO_OPEN=1 does the same as --no-open, and HOST=0.0.0.0 binds the backend to your LAN instead of localhost. The default bind is 127.0.0.1 on purpose: read Security model before you change it.

Model modes

Model mode controls where indexing and retrieval run. It is separate from your chat-model choice, which lives in the toolbar. You can set the mode at install time with the flags above, or change it any time under Settings → Model Mode (changing it prompts a reload so the app re-initializes).

ModeEmbeddingsRerankerEntity extractionOn-device weights
CloudCohere Embed v4 (Bedrock)Cohere Rerank 3.5Claude Haikunone - lean install
Hybridper-capability pickper-capability pickper-capability pickdownloaded on first index build
Local (first-run default)Qwen3 (on-device)Qwen3 RerankerGLiNER~5 GB index stack on first index build; chat models installed from Discover

The mode alone ships no on-device chat model. To chat locally, install one first from Settings → Models → Discover, which lists a recommended set (Gemma 4 12B, Gemma 4 Coder, Qwen3.5 9B, Ministral 3 14B) and grades each against your machine's memory before you download. Until you install one, local mode still lists the cloud models in the picker, because the mode filter never leaves the picker empty: you can chat on Bedrock from the first minute and decide about on-device chat later.

Each embedder keeps its own index. Switching modes never rebuilds the other backend's index, so you re-index a folder once under a given backend to search it there. Cohere embed and rerank are pinned to us-east-1; chat can run in any region. Transcription is always on-device (Whisper, Parakeet, or Canary) in every mode.

For the full picture of how each backend is wired, see Model modes and the architecture page Model backends & modes.

Step 5 - Configure in the app

Open the URL the script printed (something like http://127.0.0.1:8000). A one-time notice explains the three model modes and tells you that you are starting in Local mode; dismiss it, or let it take you straight to the Model mode tab. Then click the gear icon, go to Access and usage → Keys and permissions → API keys, and fill in:

Bedrock Region
The same region you used in aws configure, where Claude is enabled. It is pre-filled with us-east-1.
Tavily API Key
Only if you did not set the TAVILY_API_KEY environment variable in Step 3.

Click Save. The chat model is not a Settings field: pick it from the model chip in the composer toolbar, or with /model. Then type hello in chat. If the answer streams back, the install is verified.

Transcription needs no setup. The speech model auto-downloads on your first recording and runs entirely on your machine. There is nothing to configure to record; the Canary engine and its language-ID companion download the same way the first time you pick them.

Where settings live

Your settings live in config.user.json (at the repo root for a source install, under ~/.whisper for the Mac app). It is gitignored and holds your Tavily key, region, and anything else you change. It is not a copy of the template: config.example.json stays live as a read-only system layer beneath it, so shipped defaults and new catalog models reach you with no sync step, and your file carries only your own deltas. Environment variables override everything, and a per-project .whisper/settings.json sits between them. An older checkout that still has a monolithic config.json keeps using it as the user layer until it is migrated. See Configuration for the full layer model.

Import an existing Claude Code or Codex project

If you are coming from Claude Code or the Codex CLI, you do not have to re-create your project setup by hand. Connect the workspace, open Settings → Import project, and point it at the project. It migrates:

  • The instructions file: CLAUDE.md (Claude Code) or AGENTS.md (Codex) becomes the project's WHISPER.md.
  • Skills: skill folders (the SKILL.md convention both tools share) are copied into Whisper Studio's app-wide skills directory.
  • MCP servers: .mcp.json entries are translated into Whisper Studio's MCP configuration.

The import is copy-only: your source files are never modified, nothing it writes is executed, and it never overwrites an existing WHISPER.md, skill folder, or MCP server entry.

Troubleshooting

Most first-run problems fall into a handful of buckets. Match the symptom, apply the fix, re-run.

SymptomFix
python3: command not foundRun brew install python@3.12, then reopen Terminal.
brew: command not foundRun the two eval lines the Homebrew installer printed, then reopen Terminal.
Python 3.x detected; this project requires Python 3.12 or newerAccept the script's offer to install it, or run brew install python@3.12 yourself and reopen Terminal so the updated PATH applies.
Cannot continue without Python 3.12 or newer. Exiting.The script asked and you declined, or it is not running in an interactive terminal. Install Python 3.12 or newer, then re-run.
setup.sh: Permission deniedRun it as bash setup.sh, not ./setup.sh.
npm install network errorsYou are behind a proxy or firewall. Try another network, or npm config set registry https://registry.npmjs.org/.
Any install step failingRead the 40 lines the script prints from setup.log, or open the full log at the repo root.
AccessDeniedException / Could not invoke model in chatThe AWS user lacks Bedrock permissions, or the Claude model is not enabled in your region.
You don't have access to the model with the specified model IDRegion mismatch - the model is enabled in a different region than Settings says. Align the Bedrock Region.
The Talk button is disabledHover it: the tooltip names the reason. Usually Nova 2 Sonic is not enabled in the region, the AWS credentials are missing, or the Python running the backend is older than 3.12.
An on-device model fails with unknown model architectureThe llama.cpp build is too old. Run brew upgrade llama.cpp.
Port 8000 or 5173 already in useThe script auto-increments to the next free port. Read the URL it actually prints.
Blank page in the browserThe frontend bundle is missing. Re-run bash setup.sh, or bash setup.sh --new for a clean rebuild.

When in doubt, run /doctor. Type it in the chat input for an automated AWS-credentials and Bedrock-connectivity check that reports exactly what is missing or misconfigured.
