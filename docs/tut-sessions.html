Sessions: export, import, and fork

Every conversation is a session you can move, back up, or duplicate. Export one as a portable file, import it again on any machine, or fork it in place with Branch when you want two directions from the same point without touching the original.

A session is a row in the local database: its chat history, and any recorded transcript. That makes it durable, but also stuck on this machine unless you move it deliberately. This tutorial covers the three ways to move or duplicate a session: exporting and importing a single one, doing the same for a whole selection at once, and branching a session into a fork without any file changing hands at all.

Export a single session

Right-click (or open the row menu on) any session in the sidebar and choose Export. The submenu offers four formats, and only one of them round-trips:

FormatWhat you getRound-trips back in?
Portable backup (.jsonl)One line per transcript segment and chat message, plus a header line with the title and speaker names.Yes, via Import.
Conversation + transcript (.md)A single readable Markdown file combining both, generated in the browser.No, read-only.
Conversation (.txt)Just the chat messages, one after another.No, read-only.
Transcript (.txt)Just the transcript, with speaker names resolved.No, read-only.

Reach for the .md or .txt exports when a human is going to read the result, in an email, a wiki page, or a ticket. Reach for the portable backup when the point is to move the session itself, to another machine, into a bug report you want a developer to import and reproduce against, or as a plain backup you keep around.

The portable format is deliberately simple: newline-delimited JSON, one export_meta line (session id, title, export time, speaker names), then one segment line per transcript segment, then one message line per chat message. It is the same content a Branch copies internally, just serialized to a file instead of a database row, so nothing is lost or summarized in translation. Unknown line types are ignored on import rather than rejected, so an older export still imports cleanly even after the format gains new fields.

Import it back

Click Import in the sidebar toolbar and pick a .jsonl file (a single-session export, from this instance or another). A brand-new session is created with a fresh id, and the sidebar switches straight to it. Nothing about the original session that was exported is touched, importing only ever adds.

Import works across machines and across app instances: export on one install, copy the file over however you like (email, a shared drive, a chat attachment), and import on another. There is no pairing or account involved, the file is the whole transfer.

Select several: bulk export and import

The same two operations work on many sessions at once, from a dedicated selection mode rather than the per-session menu.

  1. Enter select mode

    Click Select in the sidebar toolbar. The list grows a tri-state checkbox at the top: unchecked (none selected), checked (every visible session selected), or a dash (some but not all). Clicking it toggles between none and all of what is currently visible, so a search filter narrows what "select all" means.

  2. Pick your sessions

    Check the ones you want. The bar tracks a live count, "3 selected", so you always know how many you are about to act on.

  3. Export, delete, or import

    Export zips every selected session's portable JSONL into one sessions-export-<date>.zip download, one entry per session (same-titled sessions get de-duplicated file names inside the zip). Delete removes every selected session after one confirmation. Import stays available here too, so importing and exporting live in the same place.

  4. Done

    Click Done to leave select mode. Nothing you did not explicitly Export or Delete is touched.

Bulk import accepts the same picker with multiple files selected: pass it several .jsonl files, or a single .zip produced by bulk export (or both), and each .jsonl entry becomes its own new session. A zip is detected by its actual content, not by the file's name, so a renamed export still imports correctly. When a batch is mixed, some files import while a bad one is reported as failed rather than aborting the whole batch, and the sidebar switches to the last session that imported successfully.

Bulk export caps out at 500 sessions in one request and bulk import at 200 files in one batch. Both are generous headroom for a whole workspace's history, not a limit you are likely to bump into; if you do, run the operation in a couple of batches.

Branch: fork a session in place

Sometimes you do not want a file at all, you want to keep the current session exactly as it is and try a different direction from the same point, without either copy affecting the other. That is Branch, in the same per-session menu as Export.

  1. Choose Branch

    Open the session's row menu and click Branch. If the session is actively streaming, its latest state is saved first, so the fork always starts from what you actually see on screen, not a stale snapshot.

  2. A new session appears, already open

    The fork is inserted as a new row with the same chat history, transcript, and speaker names, titled <original title> (branch), or (branch 2), (branch 3), and so on if you branch the same session more than once. The sidebar switches to it immediately and a toast confirms the new title.

  3. The two are now independent

    From this point the original and the branch are ordinary, unrelated sessions. Nothing you do in one is reflected in the other, and deleting either leaves the other untouched.

Under the hood this is a straight database copy, no file is written or downloaded, which is why it is instant even for a long session. It is the same content an export would serialize to JSONL, just landing directly in a new row instead of a file you would have to re-import.

Reach for Branch when

You want to try a second approach from the same conversation without losing the first, or you want a safety copy before an experiment that might go sideways, and you are staying on this machine.

Reach for Export / Import when

The session needs to leave this machine (another install, a teammate, a bug report), or you want a file you can archive outside the app entirely.

Where it all lives

GET /api/sessions/<id>/export
Streams one session as portable JSONL.
POST /api/sessions/bulk-export
Zips many sessions' JSONL exports into one download (id list, capped at 500).
POST /api/sessions/import-transcript
Creates one new session from an uploaded JSONL export.
POST /api/sessions/bulk-import
Creates a new session per file from multiple uploads or a bulk-export zip (capped at 200 files).
POST /api/sessions/<id>/branch
Copies a session's persisted content into a new session row.
server/infrastructure/sessions_routes.py
All five routes above, plus the shared JSONL line-building helper both export paths use.
src/components/layout/Sidebar.tsx
The row menu (Export, Branch), select mode, and the select-all / Export / Delete / Import toolbar.
