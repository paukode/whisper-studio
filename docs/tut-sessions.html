Sessions: export, import, and fork

Each conversation is a session. You can export a session to a portable file, import the file on a different Mac, or fork the session in place with Branch.

A session is a row in the local database. The row contains the chat history and the recorded transcript, if there is one. The session stays on this Mac until you move it. This tutorial shows three procedures: export and import one session, export and import many sessions, and fork a session with Branch.

Export one session

Right-click a session in the sidebar, or open its row menu. Then select Export. The menu shows four formats. Only the portable backup can go back into the app:

FormatContentsCan you import it?
Conversation + transcript (.md)One Markdown file with the conversation and the transcript. The browser makes the file.No
Conversation (.txt)Only the chat messages, in sequence.No
Transcript (.txt)Only the transcript, with the speaker names.No
Portable backup (.jsonl)One line for each transcript segment and each chat message, and a header line with the title and the speaker names.Yes, with Import.

Use the .md or .txt files when persons read the text. Examples are an email, a wiki page, and a ticket. Use the portable backup to move the session. For example, move it to a different Mac, attach it to a bug report, or keep it as a backup.

The portable format is newline-delimited JSON. The first line is export_meta, with the session ID, the title, the export time, and the speaker names. Then there is one segment line for each transcript segment. Then there is one message line for each chat message. Branch copies the same content, but into a database row. The app does not shorten or summarize the content.

The export contains all the rows of the conversation. This includes the cards that the app writes into the conversation, for example scheduled task results, agent reports, and messages from other sessions. The export does not contain these items:

  • The cost records of the session.
  • The uploaded attachments.
  • The source passages of a grounded answer.
  • The scheduled jobs of the session.

Import a session

The Import button shows in the sidebar toolbar when the sidebar has one or more sessions. On a new install, start one conversation first.

  1. Click Import

    Click Import in the sidebar toolbar.

  2. Select the file

    Select a .jsonl file. The file can come from this app or from a different install.

  3. Open the new session

    The app makes a new session with a new ID and opens it. The app does not change the original session.

Import operates across Macs and across installs. You do not need an account or a pairing step. The file contains all the data of the transfer. You can move the file in an email, on a shared drive, or as a chat attachment.

Import a Claude Code transcript

Import also accepts a Claude Code session. Claude Code keeps one transcript for each session in ~/.claude/projects/. The transcript is a .jsonl file with the session ID as its name. Select the file with Import. You can select it alone, with other files, or in a .zip file. The app identifies the file from its content, so you do not need to rename it. The app makes a chat session without a recorded transcript.

The import contains these items from Claude Code:

  • Your prompts, also the prompts that you added during a turn.
  • The answers and their thinking text.
  • Each tool call and its result.
  • Stopped turns.
  • Each API error and each usage-limit notice that Claude Code showed.

The import does not contain the internal data of Claude Code: system reminders, hook feedback, local slash commands, task notifications, and compaction summaries. If you went back and asked again in Claude Code, the app imports only the last branch. A compacted session starts from its first prompt.

The session gets the name that you gave it in Claude Code. If there is no name, it gets the title from Claude Code. If there is no title, it gets your first prompt. The app cuts each tool result to 2,000 characters. Each image becomes an [Image] placeholder.

Export and import many sessions

Select mode lets you export, delete, or import many sessions in one operation.

  1. Start select mode

    Click Select in the sidebar toolbar. A checkbox shows at the top of the list. The checkbox has three states: no sessions, all visible sessions, or some sessions. Click it to select all or no visible sessions. A search filter changes the visible sessions.

  2. Select your sessions

    Select the checkbox of each session. The bar shows the number, for example "3 selected".

  3. Export, delete, or import

    Click Export to download one sessions-export-<date>.zip file. The file contains one portable JSONL file for each selected session. Sessions with the same title get different file names in the zip file. Click Delete to delete all the selected sessions after one confirmation. Import is also available in this bar.

  4. Stop select mode

    Click Done. The app changes only the sessions that you exported or deleted.

To import many sessions, select many files in the file dialog. You can select .jsonl files, a .zip file from a bulk export, or both. Each .jsonl file becomes a new session. The app identifies a zip file from its content, not from its name. If one file in a batch is bad, the app shows that file as failed and imports the other files. The sidebar then opens the last imported session.

A bulk export accepts a maximum of 500 sessions. A bulk import accepts a maximum of 200 files. If you have more, do the operation in two or more batches.

Branch: fork a session in place

Use Branch to try a different direction from the same point. Branch keeps the original session as it is. Branch is in the same row menu as Export.

  1. Select Branch

    Open the row menu of the session and click Branch. If the session streams an answer, the app saves its latest state first. Thus the fork starts from the text that you see.

  2. Open the new session

    The new session has the same chat history, transcript, and speaker names. Its title is <original title> (branch). The next forks of the same session get (branch 2), (branch 3), and the next numbers. The sidebar opens the new session, and a notice shows the new title.

  3. Use the two sessions separately

    The original session and the fork are now two separate sessions. A change in one session does not change the other session. If you delete one session, the other session stays.

Branch copies the database row directly. Branch does not write or download a file, so it is fast also for a long session. The content is the same as the content of an export.

Use Branch when

You want to try a second approach from the same conversation and keep the first. Or you want a safety copy before an experiment. The session stays on this Mac.

Use Export and Import when

The session must go to a different Mac, a different install, a teammate, or a bug report. Or you want a file that you keep outside the app.

Find a session

The sidebar search box (Search conversations…) filters the sessions by title. When the box contains text, the Search message content checkbox shows below the box. Select the checkbox to also find text in messages and transcripts. Each result shows a snippet of the matched text.

The content search uses a full-text index of all the sessions. The app updates the index after each change, so the search stays fast. If the list cannot show all the matches, the box shows "not all matches shown".

The assistant can use the same index with the session_search tool. For example, ask "what did we decide about the retry policy a few weeks ago?". The tool finds the best match in each session and reads the messages near it. The tool can also read a full session. The search does not use a model. The tool returns the stored messages, not a summary.

The search also operates in the current session. In a long conversation, the app compacts the prompt: it replaces old messages with a summary. The summary contains your own old messages word for word, the newest first. The limit is 800 characters for each message and 4,000 characters in total. The stored history does not change. The summary tells the assistant how to search this session and read each old message again.

Where it all lives

GET /api/sessions/<id>/export
Sends one session as portable JSONL.
POST /api/sessions/bulk-export
Puts the JSONL exports of many sessions into one zip file. The maximum is 500 IDs.
POST /api/sessions/import-transcript
Makes one new session from an uploaded JSONL export or Claude Code transcript.
POST /api/sessions/bulk-import
Makes one new session for each uploaded file or each file in a bulk-export zip file. The maximum is 200 files.
POST /api/sessions/<id>/branch
Copies the saved content of a session into a new session row.
GET /api/sessions/search?q=
Returns the sessions that match in message or transcript text, the newest first, each with a snippet. The "Search message content" checkbox uses this route.
server/infrastructure/sessions_routes.py
The six routes above, and the JSONL line function of the two export routes.
server/infrastructure/claude_code_import.py
Reads a Claude Code transcript into a chat history for the two import routes.
server/infrastructure/session_search.py
The full-text index of the sidebar search and of the session_search tool.
src/components/layout/Sidebar.tsx
The row menu (Pin or Unpin, Rename, Branch, Export, Open workspace in, Archive or Unarchive, Delete), the search box, select mode, and the Import and Select toolbar. "Open workspace in" (VS Code, Kiro, Finder) shows only for a session that ran in a workspace.
