Talk: voice conversations

Speak to the assistant and hear it answer. It uses the same tools, the same workspace and the same approvals as typed chat, so a spoken "pull the branch" runs exactly the checks a typed one would.

This is a conversation, not dictation. You talk, the assistant talks back, and anything you ask for is actually done: files read, commands run, branches listed, documents written. Dictation (speaking a message into the chat box) and meeting recording are a different feature and stay on your machine; see Voice & meetings for those.

Your audio leaves the machine here. While a voice conversation is open, your microphone is streamed to Amazon Bedrock, and the spoken replies come back from there. That is the opposite of transcription and dictation, which run on-device and send no audio anywhere. Nothing is streamed when the conversation is off.

Start and end a conversation

The Talk button is the small equalizer icon in the chat composer, between the dictation microphone and Send. Hover it and it says "Talk with the assistant hands-free. Your audio goes to Amazon Bedrock (Nova 2 Sonic) while this is on." Click it to start and grant the microphone permission if the browser asks. The composer is then replaced by the voice bar for as long as the conversation lasts.

You can also end it by voice: say stop, goodbye, that you are done, or ask to go back to typing, and it says a short goodbye and hangs up.

Hanging up never cancels work. Requests still running keep going, their cards and activity stay on screen, and their answers still land in the chat. To stop them as well, use the Stop button that replaces Send while background work is finishing.

How it works

Two models share the conversation, and the split is the whole design:

  • Amazon Nova 2 Sonic carries the voice. It hears you and speaks back over a single bidirectional stream on Amazon Bedrock. It answers greetings and small talk itself, keeps its replies to a sentence or two, and never reads lists, paths, file names or command output aloud.
  • The chat model selected in the toolbar does the work. Anything concrete is handed to it as one written request, and it runs a normal turn with the full tool set, the connected workspace, your permission mode and this session's approvals. An on-device model cannot run these turns, so a local selection falls back to the default cloud model.

That is why a spoken request behaves exactly like a typed one: the same tools, the same approval cards, the same cost tracking, the same agents. Sonic only relays your words and speaks the gist of the answer.

You can talk over it at any time: the reply stops playing the moment you start speaking. If you say something while it is working, it keeps listening and catches up. Spelled-out names survive the trip, so "m l dash o p s" reaches the assistant as ml-ops, and for anything that changes or deletes something the assistant confirms the exact operation before running it, because speech recognition confuses pull with push and delete with delegate.

What lands in the chat

The conversation writes itself into the session you started it in, as ordinary chat messages you can scroll, copy and export later.

  • One bubble per utterance. What you said and what it said arrive as separate bubbles, each marked spoken next to its timestamp. Your speech is transcribed in pieces and merged back into a single bubble per turn; each thing the assistant says is committed once, when it has finished saying it.
  • The written answer is its own bubble. What you hear is a short spoken summary; the assistant's full written answer, with its tool activity, agent cards and any team report, arrives separately and is not marked spoken. If you ask to see the details, they are already on screen.
  • A live bubble while it works. It shows the words being spoken right now, headed Speaking with the voice name or Thinking, plus the running steps.

Approvals and questions

When the assistant needs you, its turn pauses exactly as it would in typed chat. Sonic tells you what it wants in one sentence and asks, and the usual card appears in the chat at the same time:

CardAnswer by voiceAnswer by clicking
Approval needed (with the risk badge, the command or path)Say yes or noYes or No
Question for youSay your answer in your own wordsOne button per offered option
Folder neededSay the folder name or path-

Either way answers the same pending request, and only once: a spoken "yes" and a tap on the card arriving together cannot run the action twice. Once you answer, the paused turn resumes where it stopped.

A refusal always wins. Any refusal word in what you say is read as no, even mixed with a yes ("okay, no" and "yes but don't" both deny), and an approval needs a clear approval word. A wrongly denied action costs one more question; a wrongly approved one can cost a file. An "uh huh" while it is still working is not an approval, and it never approves on your behalf. See Permissions & approvals for what gets asked in the first place.

Long tasks keep running

A quick request comes back while you wait. Anything slower keeps going in the background after about twenty seconds: it tells you it is running and stays available for whatever you ask next. Up to three requests can run at once.

  • Hang up while something is still running and the chat toolbar shows a Working in background chip until it lands, with a Stop button in place of Send.
  • When the result lands, it summarises it in a sentence or two and the full written answer appears in the chat.
  • Ask what is happening ("what is it doing?", "how far along is it?") and it reports the real requests in flight, how long they have been going, and any agents they spawned, rather than guessing.
  • A request that has run for 30 minutes is stopped, and whatever it produced is delivered with a note. Work is never silently dropped.
  • A background run can pause for an approval too. The card appears and you answer it the same way, by voice while the conversation is open or by clicking after you have hung up.

Opening a folder by name

Say "open the ml-ops folder in Documents" and the assistant looks the name up instead of guessing a path. Spoken punctuation is folded first ("dash", "underscore", "dot"), matching ignores case and punctuation, so ml-ops, ML_OPS and "m l dash o p s" all find the same directory. It searches the folder you named, the usual home folders (Documents, Desktop, Downloads, Developer, Projects and friends) and the parents of workspaces you opened recently.

One confident match is opened. When several folders could be it, you are offered the real names that exist and asked which one; a name that matches nothing is never invented. Connecting a workspace this way switches the app to it exactly as the workspace picker would.

Type without hanging up

Press Type instead (voice stays on) in the voice bar, or the Voice on chip in the toolbar, and the text box comes back with the conversation still open. What you type is heard by the conversation as if you had said it, so you can paste an exact command or a long path instead of spelling it out. Press the chip again (or the Talk button) to return to the voice bar.

Recording, hands-free. Ask it to start or stop recording the meeting and it drives the Record button for you, so a call can be captured without touching the keyboard. The transcript itself is still produced on-device.

Voice and language

The voice bar shows which voice is speaking and the locale it belongs to. There are sixteen Nova 2 Sonic voices: Tiffany (the default) and Matthew are polyglot and speak every supported language, while the rest are tied to one locale - Amy (en-GB), Olivia (en-AU), Kiara and Arjun (en-IN), Ambre and Florian (fr-FR), Beatrice and Lorenzo (it-IT), Tina and Lennart (de-DE), Lupe and Carlos (es-US), Carolina and Leo (pt-BR).

There is no picker in the window. Change the voice in the config editor (Settings, then the config.json dialog) by setting voice.voice_id, and set voice.endpointing to change how long a pause has to be before it takes your turn as finished. Both apply to the next conversation you start.

Before you start

  1. Enable the model in Amazon Bedrock

    Your account needs access to amazon.nova-2-sonic-v1:0 in the region voice mode uses. That region is voice.region, and when it is blank (the default) it follows bedrock_region, which itself defaults to us-east-1. Nova 2 Sonic is offered in us-east-1, us-west-2, eu-north-1 and ap-northeast-1 only, so a chat region outside that list needs voice.region set explicitly.

  2. Check your credentials

    Voice mode uses the same AWS credentials as the rest of the app (aws configure, AWS_PROFILE, or SSO). A Bedrock API key (AWS_BEARER_TOKEN_BEDROCK) is not accepted by this API: it requires signed requests.

  3. Python 3.12 or newer, for a source install

    The bidirectional stream needs the aws-sdk-bedrock-runtime package with its awscrt transport, which installs only on Python 3.12 or newer. setup.sh requires that version anyway and installs the package for you. The Mac app ships its own Python and the SDK inside the bundle, so there is nothing to install there.

  4. Allow the microphone

    The first conversation asks for the microphone, as recording does. Voice mode opens its own stream with echo cancellation, because the reply is playing out of the same speakers. Headphones still help in a noisy room.

What leaves your machine

While the conversation is open, your microphone audio goes to Amazon Bedrock and the spoken replies come back from it, together with the text of the conversation. The assistant's own work runs where it always does: on your chat model, with the tools reading your files locally. Meeting transcription and chat dictation are unaffected and still never send audio anywhere, so the honest summary is: recording stays local, talking does not. End the conversation and the stream is closed.
