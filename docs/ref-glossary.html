Glossary

The vocabulary of Whisper Studio, defined the way this project uses each term. Where a concept has its own page, the entry links to it.

Terms are grouped alphabetically. Many of these words have broader meanings in the wider industry; the definitions here describe how Whisper Studio specifically uses them. When in doubt, the linked architecture page is the source of truth.

Looking for something specific? Press / (or click the search box in the sidebar) to filter every page, including this one, by term.

A - B

TermDefinition
agent journal (flight recorder) The on-disk record every agent run writes while it is alive, from its first round: <storage>/agents/<session>/<agent>/ holding meta.json (task, type, model, budgets, status, stop reason, usage), events.jsonl (every progress event as it happened), messages.json (the message list, rewritten each round) and report.md. It makes the record primary rather than something the parent's context holds: journals survive a restart, task_output <id> tails a live agent or returns a finished one's report, and messages.json is what lets a stopped agent be resumed with its context intact. See The agent flight recorder.
agent report The last thing an agent writes: a fixed-shape summary (findings, evidence, what was not checked, confidence, files touched, and one quotable line) produced in a reserved final round. The caller gets that text, not a transcript, and is reminded that you never saw it and must relay what matters. Compare salvage report. See The agent flight recorder.
agent report card The chat card that appears when agent reports arrive with no turn running, because you pressed Stop or the app restarted. It lists each agent's report and comes with a notification. The parent then wakes (see that entry) to actually answer from them.
approval pause The server-side hold on a turn that needs consent. When a tool needs approval, the engine stashes the in-flight turn in paused_sessions and only resumes it once the client posts back the registered action tied to that tool call's tool_use_id; the executor re-validates the payload itself at execute time rather than trusting anything the client asserts. This is why command approval is a real boundary and not client-asserted. See Approval & permissions.
ASR Automatic Speech Recognition. The task of turning audio into text. Whisper Studio runs ASR entirely on-device (Whisper, Parakeet, or Canary) in every model mode, so recorded audio never leaves your machine. Voice mode is the exception and is a different feature. See Transcription & diarization.
auxiliary models The map that names which model runs each side task the assistant does on your behalf: memory recall, the goal evaluator, session titling, the auto-mode classifier, the permission explainer, query rewriting, CI diagnosis, compaction and the post-turn learning review. Values are chat_models keys, and "main" means the session's own model. An empty map (the default) leaves every task on its historical default. See Settings & config keys.
Bedrock Amazon Bedrock, the AWS managed service Whisper Studio uses to call Claude (and GPT) for chat. Two distinct endpoints, depending on the model: Claude goes straight to bedrock-runtime.<region>.amazonaws.com via invoke_model_with_response_stream; GPT goes to bedrock-mantle.<region>.api.aws's OpenAI-compatible Responses API. Voice mode is a third Bedrock surface, a bidirectional stream to Nova 2 Sonic. All cloud model calls the app makes go to Bedrock; there is no other provider. See Model backends & modes and the Amazon Bedrock docs.
BlackHole A macOS virtual audio driver used to route system audio into a recording. Paired with an Aggregate Device, it lets a meeting recording capture both your microphone and whatever macOS is playing. Install with brew install blackhole-2ch. See Voice & meetings.
busy slot The per-session claim that says a turn is running. Every turn takes it, continuations after an approval included, so a second turn cannot start on top of one in flight: it gets a 409, or, when it is a mid-turn message, is queued into the mid-turn inbox. A heartbeat refreshes the slot while the turn is silent, so an hour of agents or one long shell command does not look abandoned; a slot with no heartbeat for 15 minutes is reclaimed as stale. See Anatomy of a chat turn.

C

TermDefinition
Canary One of the three on-device speech-recognition engines (Canary 1B v2, a vendored MLX port). The fastest of the accurate engines and the app's universal model translator: transcribes 25 European languages with live word-by-word drafts, and translates between any of them and English whichever engine is transcribing. Having no language head of its own, it pairs with the VoxLingua107 language ID classifier. It does not report word timestamps, so speaker turn splitting does not run on Canary audio. See Transcription & diarization.
chat turn One request/response cycle: your message plus everything the assistant does to answer it (streamed text, thinking, tool calls, approvals) up to [DONE]. A single turn is one POST /api/chat that streams back over SSE and may run an agentic tool loop of up to 50 rounds. See Anatomy of a chat turn.
cron_event A chat-history row produced by a scheduled (cron) task. Cron output cards persist on disk and render in the chat, but visible_chat_history filters them out before the next prompt is built, so a job firing frequently never inflates the token bill. See Cron / scheduled tasks.

D - E

TermDefinition
destination_path The parameter that resolves where a direct-saved file lands, taken from your own words rather than asked for: "put it in Downloads" becomes ~/Downloads/<filename> (a ~ path is allowed); naming no location falls back to ~/Documents/<filename>. Used by save_file, ws_create_file without a workspace, and the document tools. See the staging area entry and The direct-save flow.
detached / worktree agent An agent started in the background rather than inline. spawn_agent with detach: true returns a task_id at once (read-only by default) so the turn is not blocked; isolation: 'worktree' additionally runs it inside an isolated git worktree so its edits never touch your current checkout. Complements the sub-agent and worktree entries. See Sub-agents & the event bus.
diarization Assigning "who spoke when" to a transcript. Whisper Studio embeds each utterance with a speaker encoder (ReDimNet2 by default, ECAPA as the fallback), clusters the vectors, and cuts an utterance at a handover when speaker turn splitting finds one. Labels hold per session across reconnects so you rename a speaker once, and a voiceprint carries that name into later recordings. See Transcription & diarization.
Discover / memory-fit The model browser under Settings > Models > Discover. The app ships with no local model installed by default; Discover lists recommended on-device models you can install, each graded by whether it actually fits your device's memory before you download it. See Settings & config keys.
DOMPurify The HTML sanitizer (version 3.4.6) that every Markdown render passes through before it reaches the React DOM. It strips <script>, inline event handlers, and javascript: URLs, so a prompt-injected page fetched by web_fetch cannot run arbitrary JS in the SPA origin. See Security model.
ECAPA ECAPA-VoxCeleb, the speaker encoder Whisper Studio used before ReDimNet2 and now keeps as the automatic fallback: ReDimNet2 arrives over the network on first use, and a blocked or offline first run should degrade to a working encoder rather than to no speaker labels at all. Select it explicitly with speaker_embedder: "ecapa". A separate ECAPA model does spoken-language ID; the two share an architecture, not a job.
effort level How much reasoning budget the model spends per turn: low, medium, high, extra (the raw name xhigh is an alias), max, or ultracode. The former auto level is retired (coerced back to a real level). ultracode is a session mode that pairs top reasoning effort with dynamic-workflow orchestration. Set it with the /effort command or in Settings. See Settings & config keys and The ultracode workflow runtime.
elicitation A mid-call question a connected MCP server asks the human directly, rather than answering itself. Whisper Studio never lets a server ask silently: an elicitation is surfaced through the approval pipeline under its own category, mcp-elicit. See Security model.
embedding A numeric vector that represents the meaning of a chunk of text so similar passages sit close together. Used by the index to find relevant context for grounding. The embedder depends on model mode: Cohere Embed v4 in cloud, Qwen3 on-device in local. See Index / GraphRAG & search.
entity A named thing (person, file, project, concept) extracted from your indexed content and wired into the knowledge graph. Entities are extracted by Claude Haiku in cloud mode and by GLiNER on-device. See Index / GraphRAG & search.
ephemeral agent type An agent type defined inline for one spawn_agent call via agent_definition (name, description, system prompt, optional tool whitelist) when no registered type fits. Nobody reviews the definition before it runs, so it defaults to a read-only tool pool unless tools or read_only says otherwise. A good one can be kept as a persistent custom type with promote_agent_type, which saves it to .whisper/agents/<name>.md. See Agent tools.
event bus The per-session publish/subscribe channel (server/agents/event_bus.py) that fans sub-agent and team activity out to the browser over SSE. Spawns, progress, and completions all travel across it. See Sub-agents & the event bus.
Extend The button on a running agent's budget bar that grants it 20 more rounds while its context is still loaded, instead of letting it stop at its limit and resuming it later with a reloaded context. The runner reads the grant at the start of its next round. See The agent flight recorder.

G

TermDefinition
GLiNER An on-device model used for entity extraction when the app runs in local mode (the cloud equivalent is Claude Haiku). It feeds the knowledge graph without any network call. See Index / GraphRAG & search.
goal / goal gate A per-session objective the assistant works toward. Set it with /goal (and /goal clear to end it); it is stored on the session row and a goal banner shows above the composer. After each turn a completion gate - a cheap evaluator in server/goals/gate.py - judges whether the goal is met, and if not the goal loop auto-continues the turn, capped at 8 consecutive blocks (goal_max_consecutive_blocks). Gated by the goal_loop feature flag. See The goal loop & completion gate, and compare quality gate and verification gate, the two deterministic checks that run inside the same gate.
GraphRAG Retrieval-augmented generation that combines vector search over embeddings with a graph of entities and their relationships, rather than plain nearest-neighbour lookup. It powers workspace indexing and the grounding chip shown during a turn. See Index / GraphRAG & search.
grounding Injecting passages retrieved from a selected workspace index into the prompt so the answer is anchored to your own documents. A "grounding" chip over SSE reports which folders were searched and how many passages were retrieved. See Index / GraphRAG & search.

H - L

TermDefinition
hook A user-defined gate that runs at a fixed point in a turn: PreToolUse (can deny or rewrite a tool call), PostToolUse (can inject additional context), and a Stop gate, wired across chat, sub-agents, and cron (server/hooks/). User hooks live in hooks.json; a workspace may also ship trust-gated project hooks in .whisper/settings.json that stay inert until explicitly trusted. Managed in Settings, not from a slash command. See Blocking hooks.
hybrid mode One of three model modes. In hybrid mode you pick a backend per capability (embeddings, reranker, entity extraction, the indexing writer), mixing cloud and on-device; the on-device weights download on first use. A fresh install is seeded to local, not hybrid, but with the hybrid backend map already filled in, so switching to hybrid picks up on-device embeddings and reranking (Qwen3), GLiNER entity extraction and cloud Haiku as the writer. Compare cloud and local. See Model modes and Model backends & modes.
import project A one-shot migration from a Claude Code or Codex CLI project into Whisper Studio: its instructions file (CLAUDE.md or AGENTS.md) copies to WHISPER.md, its skills copy across, and its .mcp.json translates into MCP server config. Never overwrites existing files, and nothing imported runs as part of the import. Run it from Settings > Tools and automation > Import project. See Settings & config keys.
language ID Deciding which language an utterance is in, as a separate step from transcribing it. Whisper Studio uses VoxLingua107 ECAPA, one of the three speech models that ship bundled with the app. Whisper has its own language head and does not need it; Canary has none, so it pairs with this classifier. Constrain what it may choose with the Whisper Language setting. See Transcription & diarization.
llama-server One of the two on-device chat engines: upstream llama.cpp's own server, run as a subprocess serving GGUF weights over an OpenAI-compatible API. It is a subprocess rather than in-process bindings because llama.cpp owns the tool-calling and reasoning parsers for every model family it supports, so a new GGUF gets tool calls and a thinking channel with no per-family parser written here. One model is resident at a time; switching models stops the old process first. Compare MLX engine. See Model backends & modes.
loop guard The per-turn guard that stops a model going in circles. It refuses a tool call that repeats the same arguments after two identical results, one that has already failed three times unchanged, and a repeating cycle of calls, each with a note so the model changes course. It also caps the two runaway-prone tools per turn (web search and delegation, tunable through tool_loop_caps), and replaces a byte-identical large payload with a stub pointing at the earlier result. Pollers such as task_status and sleep are exempt from the repeat checks. Gated by the tool_loop_guard feature flag. See Settings & config keys.
LSP Language Server Protocol. Whisper Studio proxies python-lsp-server and typescript-language-server to power the lsp_diagnostics, lsp_hover, and lsp_references tools, giving the assistant real type information about your code. See Git integration & LSP.

M - N

TermDefinition
Map-reduce condensation Splitting an oversized transcript into overlapping chunks, extracting the salient material from each with a fast one-shot model (the map step), then letting the main chat model compose the summary from the concatenated extracts (the reduce step). Extracting rather than prose-summarising is what keeps owners, decisions, and numbers intact where a plain truncation would lose them. See Transcript summarization & condensation.
MCP Model Context Protocol. A standard for exposing tools from external systems. Whisper Studio spawns local MCP servers as stdio child processes, and connects to remote servers over streamable HTTP (a url plus an optional bearer token read from an environment variable). Each server can also carry its own approval mode and tool allow/deny lists. Configure servers in Settings. See MCP & plugins and the per-server MCP fields.
mid-turn message A message you send while the assistant is already working. Instead of being refused or dropped, it is folded into the running turn: it goes to the per-session mid-turn inbox, the turn engine drains that inbox once per round, and the text is appended to the live message list so the model sees it, addressed, before its next tool call. A short notice confirms it went in. If the turn has just finished you are told nothing was sent, rather than a second answer starting. Works after an approval card too. See Anatomy of a chat turn.
MLX engine The second on-device chat engine, beside llama-server: mlx_lm server running inside the app's own Python, serving MLX-format weights (a safetensors directory rather than one GGUF file) over the same OpenAI-compatible API, so the rest of the stack is shared. Availability is an import check, not a binary lookup, and the context window is whatever the model's own config carries. A model declares which engine it wants in the catalog. See Model backends & modes.
model mode Where indexing and retrieval run: cloud, hybrid, or local. cloud is the shipped SYSTEM value, but a fresh install (setup.sh or the Mac app alike) seeds local into the user layer, which outranks it, so local is what a new install runs. This is separate from the chat-model choice in the toolbar. Cohere embed/rerank are pinned to us-east-1; chat can run in any region. See Model modes and Settings & config keys.
network egress policy An opt-in, default-off restriction on what sandboxed commands can reach on the network: a network_policy.tier of permissive (default, unrestricted), curated (a seed allowlist plus your own additions), or restrictive (only domains you add). Enforced by a local proxy that reads only the TLS ClientHello's SNI hostname, never the traffic itself. See Security model.
Nova 2 Sonic Amazon Nova 2 Sonic, the speech-to-speech model on Bedrock that carries a voice mode conversation: it hears your microphone and speaks the replies, over one bidirectional stream. Default model id amazon.nova-2-sonic-v1:0, available in us-east-1, us-west-2, eu-north-1 and ap-northeast-1 only, with sixteen voices across nine locales. It is not the model doing the work: the session's own Claude or GPT model still answers and uses the tools. See Voice conversations.

O

TermDefinition
One-shot completion A single non-streaming prompt and response, used by the map step of map-reduce condensation. It is mode-aware - Claude Haiku in the cloud, the resident model on-device - and raises on failure so the condenser can fall back to a truncated transcript instead of returning nothing. See Transcript summarization & condensation.

P - Q

TermDefinition
Parakeet One of the three on-device speech-recognition engines (the others are Whisper and Canary), and the default. Lowest latency: words appear live as you speak, in 25 European languages. It cannot translate on its own, but Canary can translate whatever Parakeet transcribes. It reports word timestamps, so speaker turn splitting works with it. All three engines keep recorded audio local. See Transcription & diarization.
permission mode The dial that decides how tool calls are gated: default (reads free, writes ask), auto (a classifier decides per call), plan (workspace writes hard-blocked, a proposal comes back), acceptEdits (edits auto-approve), bypassPermissions (no prompts), or dontAsk (reads allow, writes silently deny). Per-tool rules override any mode, and three things ask no matter what: destructive GitHub actions, an rm-class command, and a request to escape the sandbox. See Permissions & approvals.
plugin An opt-in Python file in plugins/ that adds custom API routes and tool executors. Dropping a file in does nothing until you enable it in Settings, which closes the drive-by "plugin over chat" attack vector; enabling then applies live, with no restart needed. A restart is only required to fully unload a plugin you disable after it registered hooks or routes. See MCP & plugins.
progressive tool disclosure Sending the model a core tool set plus any session-activated tools, with everything else represented only by a compact index in the cached prompt block; deferred tools are pulled in on demand via tool_search (server/chat/tool_partition.py). This cuts roughly 60-75% of the tool-schema tokens per turn. Gated by the progressive_tools feature flag. See Settings & config keys.
prompt cache layers The ordering that makes Bedrock prompt caching pay off. The system prompt is assembled from named sections on six layers: IDENTITY, MODE, WORKSPACE, DYNAMIC, TOOL_GUIDANCE and EXTENSION. Everything at or below WORKSPACE is the static block and is cached; anything that varies per request has to ride DYNAMIC or later. Parking session-stable text on a dynamic layer re-bills it every round, and rewriting the static block mid-session throws the cache away, which is why plan mode deliberately sits on the uncached tail and why seven config keys are latched per session. Cache checkpoints are then placed on the tool block and on the static system block. See Chat & tool orchestration.
quality gate A shell command that must exit 0 before a goal can be judged done. Add one with /goal gate add <command>. Gates run at every turn boundary while the goal is active, and they run before the evaluator: a red gate is deterministic proof the goal is not met, its exit code and output tail become the continuation feedback, and the model judge is not called at all. A failed gate is re-run against the current tree each boundary, so a repaired one passes next time; after three failed attempts the gate pauses the goal instead of looping. See The goal loop & completion gate.
Qwen3 The on-device model family used for embeddings and reranking in local mode (Qwen3 embedder and Qwen3 Reranker). It lets indexing and retrieval run without any cloud call. See Index / GraphRAG & search.

R - S

TermDefinition
ReDimNet2 The default speaker encoder (the B2 variant): 3.6M parameters, a 15 MB checkpoint, 0.57 percent equal error rate on VoxCeleb1-O against ECAPA's roughly 1 percent. The gap widens on the short windows this app actually feeds it, because speaker turn splitting embeds slices of about 1.25 seconds and ECAPA was trained for about 3. Its weights ship inside the Mac app and setup.sh fetches them for a source install; failing that it downloads on first use and falls back to ECAPA. See Transcription & diarization.
reranker A second-pass model that reorders retrieved passages by relevance to the query, sharpening what actually reaches the prompt. Cohere Rerank 3.5 in cloud mode, Qwen3 Reranker on-device. Off by default (the rag_reranker feature flag turns it on). See Index / GraphRAG & search.
salvage report The report the runtime assembles from an agent's journal when the agent never got to write one itself: it was cancelled, or it crashed. The team card marks that agent "salvaged" so you can tell a reconstructed record from the agent's own words. See The agent flight recorder.
sandbox-exec The macOS kernel-level sandbox (sandbox-exec(5)) that wraps every shell and code-execution path, including the terminal PTY. It is the security boundary the project trusts last and most; a curated deny-list masks secret stores (SSH/GPG keys, cloud and git credentials, browser cookies, shell history). On Linux the equivalent is bwrap. See Sandbox & security.
session content search Full-text search across every past session by what was actually said, with no model call. One SQLite FTS5 index mirrors each session's stored history and serves both the sidebar's content search and the model's own session_search tool, which can quote exact messages and read around them. It is what makes compaction recoverable: the request-side history gets summarized, the persisted history does not, so a summarized-away message can be pulled back verbatim, and every compaction summary carries a pointer saying so. Gated by the session_search feature flag. See Sessions.
session export A portable copy of your chat sessions, separate from /export's plain-text transcript. Export one session as .jsonl (GET /api/sessions/{id}/export) or many at once as a zip (POST /api/sessions/bulk-export), each with a matching import endpoint, from the sessions sidebar. See Slash commands.
skill A Markdown-defined capability the assistant loads when relevant, bundled as files in skills/ (catch-up, meeting notes, presentation builder, translate text, and more). The former built-in skills - web search, Python execution, transcript summarization, document analysis - are native tools now, not skills; see Built-in core tools. Invoke or list your own skills with skill_invoke and skill_list. See Skills.
soft limit / reserved reporting round How an agent is guaranteed to leave a report instead of being cut off mid-sentence. At 90 percent of its time or cost budget, or one round from its turn cap, the runtime declares the next round the final one, withholds tools, and appends the report template to the prompt. The budget bar shows that reserved slice marked off at the end and flips the agent's pill from "working" to "finishing up". The main turn gets the same courtesy at the session cost cap: one last round to answer. See The agent flight recorder.
speaker turn splitting Cutting one recorded utterance where the speaker changes, instead of labelling the whole thing as one person. The silence detector flushes on silence, not on handovers, so "...that's my point." / "Right, but" lands in a single utterance. The splitter slides a 1.25 second window across it, compares each side of every candidate cut, keeps the strongest peaks and snaps each to a word boundary. It needs word timestamps, which Whisper and Parakeet report and Canary does not. The word or two that genuinely overlap are marked as overlapping rather than given a pretend-precise cut. Controlled by speaker_split_turns, on by default.
SSE Server-Sent Events. The one-way HTTP streaming used to push chat tokens, tool activity, usage counters, and sub-agent events to the browser as they happen. A chat turn is an SSE stream, not a single JSON body, and it ends with [DONE]. See Chat & tool orchestration.
staging area The app-sandbox scratch directory (scratch/_staging, stage_file_bytes in server/workspace/paths.py) where a direct-saved file's full content is written before its approval card ever appears. Approving runs the save_to_path action, which re-checks the source is inside the staging root and then moves it to the resolved destination_path; declined or abandoned entries are garbage-collected after 24 hours. See The direct-save flow and Security model.
stop reason Why an agent run ended, recorded in its journal and shown on its row: completed, turn_limit, deadline, cost_cap, cancelled or error. A team result carries each member's full report with its stop reason and a pointer to its record, so "stopped at the time limit, report written" reads differently from "cancelled, report salvaged". See The agent flight recorder.
sub-agent An independent agent spawned to handle a focused subtask, coordinated through the event bus and optionally organized into a team of parallel agents. Spawn one with spawn_agent or the /subagent command. See Sub-agents & the event bus.

T - V

TermDefinition
task registry / background task The unified store of long-running background jobs - shell commands, agents, workflows, and CI watches - in the agent_tasks table (server/tasks/). Exposed at /api/background-tasks and surfaced as a running-count pill in the header; it replaced the older server/background_tasks.py. See Sub-agents & the event bus.
Tavily The web-search provider behind the web_search tool. It is optional: without a TAVILY_API_KEY, web search is unavailable and everything else, including web_fetch, still works. The env var overrides any key stored in your user config file. See Web research and app.tavily.com.
Transcript condensation The server-side step that shrinks a transcript too large for the model context before it enters a chat turn, so summarize_transcript or the main model never silently truncates or overflows the request. See the Map-reduce condensation entry and Transcript summarization & condensation.
truststore The library Whisper Studio installs at boot so TLS verification consults your macOS keychain as well as the bundled certifi CA list. Without it, a site behind a corporate or government root fails to verify in the app while opening fine in your browser. It widens which roots are trusted, not whether certificates are checked, and it fails open to certifi-only if it cannot install cleanly. See Security model.
ultracode Whisper Studio's top reasoning mode: the model authors a deterministic JavaScript workflow script that a Node-22 vm harness runs detached over stdio JSON-RPC into Python, on both Claude and GPT-on-Bedrock, with 16-way agent concurrency, a 1000-agent lifetime cap, output-token budgets (600,000 by default), a resumable journal, and upfront phase-preview approval of every new script. It is also the highest /effort level. See The ultracode workflow runtime.
utterance The unit a recording is cut into: one stretch of speech between two silences, flushed by the VAD buffer and handed to the transcription engine as one piece. Speaker labels, language detection and the translation line all attach per utterance. Because the buffer flushes on silence and not on speaker change, a handover with no gap lands inside one utterance, which is what speaker turn splitting exists to fix. In voice mode the same word means one spoken turn, and each gets its own chat bubble.
VAD Voice-Activity Detection. Distinguishes speech from silence in the audio stream, deciding where one utterance ends and keeping the transcript clean. Whisper Studio uses WebRTC VAD locally, with automatic gain in front of it so a quiet microphone still registers. See Transcription & diarization.
verification gate The check that stops "done, the tests should pass" from ending a turn. It is passive: it never runs a suite itself, it reads the turn's own messages and asks which code files were edited, which test, lint, typecheck or build commands ran afterwards, and whether they passed. When code was edited with no fresh passing evidence, the completion gate asks for a real verification or an honest blocker, at most twice per turn. Prose-only edits never trigger it. Gated by the verify_on_stop feature flag. Compare quality gate, which is a command you named rather than an inference.
voice mode (Talk) A spoken conversation with the assistant, opened with the Talk button beside the composer. Nova 2 Sonic carries the voice while the session's own model does the work through the same tools as typed chat, so it can read files, run commands and delegate. Approvals are asked aloud and shown as the usual card. The composer is replaced by a voice bar (Type instead, Mute, End); one bubble is written per utterance, so the conversation is in your history afterwards. Long delegated work keeps running in the background and is reported back, and hanging up never cancels it. Distinct from dictation (speaking one message into the composer) and from meeting transcription. See Voice conversations.
voiceprint A stored speaker embedding with a name on it, so somebody who spoke in an earlier recording is recognised in this one. Enrolling is a side effect of the rename you already do: naming "Speaker 2" stores that cluster's centroid. Matching is deliberately conservative, needing both a high similarity and a clear margin over the runner-up, because putting the wrong name on somebody is worse than leaving them as "Speaker 3". Entries are filed per encoder, since ReDimNet2 and ECAPA vectors are not comparable. Controlled by speaker_voiceprints, on by default.

W - Z

TermDefinition
wake (answering from reports) What happens when agent reports land in a session with no turn to read them, because you pressed Stop or the app restarted. If a turn is still running, the reports go in through the mid-turn inbox like a message you typed. If none is, a one-round synthesis turn starts on the session's model with the original request plus the reports, and posts its answer as an assistant bubble labelled "Answered from the agents' reports". It never opens new work: one round, no tools. One wake per session at a time, skipped with a notification when the session cost cap is reached, and turned off entirely by wake_parent_on_reports. See The agent flight recorder.
WAL Write-Ahead Logging, the SQLite journaling mode Whisper Studio runs sessions in. It lets reads and writes proceed concurrently, which matters when a background cron daemon appends rows while the frontend saves. See Persistence.
WHISPER.md A project-context file you drop in your workspace root. Its contents load into the system prompt on every chat turn, the way CLAUDE.md works for the Claude Code CLI. Edit it through the in-app Project Memory dialog or any editor. See Memory & WHISPER.md.
Whisper The on-device speech-recognition model that gives the app its name (Whisper Studio runs the full large-v3 checkpoint via mlx-whisper). The most accurate engine, with 99 languages and per-utterance language detection; Parakeet and Canary are the alternatives. See Transcription & diarization.
workflow runtime The subsystem behind ultracode (server/workflows/): a WorkflowRun that enforces the concurrency semaphore, output-token budget, and resume; the Node-22 harness (harness.mjs, guards.mjs, api.mjs); the workflow_runs table; and the workflow_run / workflow_status / workflow_save / workflow_list tools, available only in ultracode mode. See The ultracode workflow runtime.
workspace The folder you connect so the assistant can read, edit, run, and commit within it. Every file operation is validated to stay inside the workspace root, and project files like WHISPER.md and .whisper/ live there. See The workspace IDE.
workspace-write (sandbox mode) The sandbox write mode that denies every write and then allows back only the command's own working tree, the git directories a linked worktree needs, and system temp. It is the default for run_python and terminal_run, and it is what every unattended agent command gets, so the OS rather than the prompt bounds what a delegated agent can touch. The other two modes are read-only and, behind a written justification and an unconditional approval card, danger-full-access. See Security model.
worktree An isolated Git working tree on its own branch, created so the assistant can make changes without touching your current checkout. Task worktrees, managed with ws_create_worktree, ws_diff_worktree, and ws_merge_worktree, live under <repo>/.worktrees/<name> on branch whisper/<name>. Separately, a whole chat session can be pinned into its own worktree via the enter_worktree / exit_worktree approval actions, under <repo>/.whisper/worktrees/<slug> on branch worktree-<slug>, persisted across restarts. A worktree-isolated agent (see the detached/worktree agent entry) gets a third variant, brought back by the worktree harvest. See Git integration & LSP and Agent tools.
worktree harvest How a worktree-isolated agent's work comes back. An agent has git tools, so it may leave its work committed, uncommitted, or a mix; the harvest materializes the whole delta since the branch point into the originating working tree, uncommitted, so git status shows it for normal review. It works file by file off the git object database, which handles committed work, binaries, deletions and executable bits, and lets non-conflicting files land even when one file collides. A file counts as a conflict only when the main tree changed it away from the base and differently from the agent; those are left behind in the worktree, which is kept, and the note says where. Nothing is ever committed or force-resolved on your behalf, and an agent that stopped early keeps its worktree for inspection instead of applying partial work.

Whisper (the speech model) and Whisper Studio (the app) are different things. When these docs say "Whisper" alone in a transcription context, they mean the model; the product is always "Whisper Studio". Three separate things involve your voice, too: dictation speaks one message into the composer, meeting transcription records and writes up a conversation, and voice mode is a spoken conversation with the assistant. Only the last one sends audio anywhere.
